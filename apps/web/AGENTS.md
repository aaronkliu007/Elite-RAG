# 前端界面与交互规则

适用于本目录下的页面、组件及其测试。设计以用户的工作内容和操作为中心，优先保证信息密度、可理解性和可操作性。

## 信息层级与空间

- 导航已经明确当前页面时，不要再添加同名的大标题或独占一行的标题区。必要的无障碍语义可以使用视觉隐藏的标题，但不要为了填充页面添加副标题、口号、说明卡片或面包屑。
- 将空间切换、搜索、筛选和主要操作尽量组合到同一工具栏；少量选项优先使用紧凑控件。不要为单个选择项保留整列或大面积空面板。数据列表、正文及用户正在操作的内容优先使用可用空间。
- 保留帮助用户作出决定的内容，如权限、错误、处理状态、文件类型和限制；不要为了精简而隐藏关键状态、操作或安全提示。技术标识默认不占据列表主视觉区，仅在排障或确有业务需要时展示。
- 一个操作组保持清晰的主要操作；界面不因权限或状态变化出现空白容器。长名称需要可读、可查看完整内容，空数据和多数据场景均须合理。

## 验证

- 每次改动页面后，运行相关单元和浏览器测试，在真实渲染页面核看宽桌面与约 1366px 宽度；涉及移动端时检查窄屏、键盘焦点和横向溢出。测试使用模拟接口时须明确说明，不能当作真实后端验收。
- 检查导航、标题、工具栏、列表、空态与错误态是否存在重复信息、无功能的大块留白或被遮挡的操作；同类问题出现在其他相关页面时一并处理或明确列出未覆盖范围。
- 对可自动验证的页面结构、切换和空间占用补充有意义的回归测试。不能只凭截图或自动化断言声称全部视觉体验已经通过验收。
- 保持服务端权限校验、严格拒答和现有业务交互；不要把前端隐藏当作安全控制。
