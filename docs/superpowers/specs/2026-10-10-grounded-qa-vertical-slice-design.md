# 企业知识库可信问答纵向闭环设计

**日期：** 2026-10-10

**适用阶段：** 方案 A 第二条纵向闭环

**状态：** 已完成会话评审，待书面规格确认

## 1. 背景与目标

仓库已经完成知识库核心管理闭环，具备本地身份、固定角色、知识空间与文档权限、六类文件解析、人工审核发布、PostgreSQL 权威鉴权、OpenSearch 全文与向量投影、来源定位和 Vue 管理界面。当前员工能够安全地沉淀、审核、检索和查看知识，但系统尚不能基于这些受控知识生成可验证答案，也没有经量化的检索与回答质量发布底线。

本批目标是在现有 Spring Boot 核心应用内交付一条单轮可信问答纵向闭环：

> 用户提问 → 混合召回 → PostgreSQL 最终鉴权 → 重排与证据筛选 → 最小必要内容脱敏 → 经审批云模型生成 → 引用校验 → 回答或严格拒答 → 黄金集离线评测。

成功标准不是“模型能够输出文字”，而是有权用户能够获得由当前已发布知识直接支持、引用可定位的答案；当证据不足、互相冲突、不可安全外发或无法验证时，系统稳定拒答。任何未授权内容都不得进入模型请求或最终响应。

## 2. 已确认约束

- 固定工作目录为 `E:\git_repo\Elite-RAG`。
- 文档、界面、运行手册和交付说明使用中文。
- 首版采用单轮问答，不保存或自动拼接多轮对话上下文。
- 回答只能依据当前用户有权访问、已经发布的知识，不使用模型通用知识补充事实。
- 证据不足、证据冲突、授权复核后无证据、模型调用失败或引用无法验证时严格拒答。
- 数据和权限事实留在内网；只允许调用经过审批的云模型 API。
- 云模型只接收当前用户有权访问的最小必要文本片段；原始文件、完整文档、ACL 和用户身份信息不得发送。
- 外发前执行敏感信息检测与脱敏；脱敏器异常时失败关闭。
- 调用审计记录供应商、模型、配置版本、耗时、Token、脱敏数量、结果码和摘要哈希，不保存完整提示词、原始问题、证据正文或模型原始响应。
- 在现有 Spring Boot 核心应用内完成问答编排；Python Worker 继续只负责无状态文档解析。
- 通过自有端口隔离模型供应商，首个生产适配器使用 OpenAI 兼容协议，但业务代码不依赖具体 SDK 或供应商。
- PostgreSQL 是用户、发布状态、ACL 和最终授权的唯一权威源；OpenSearch 只负责可重建的候选召回。
- 每家公司独立部署一套实例，不在本批引入 SaaS 多租户。
- 钉钉身份与组织同步、报表处理、方案工作台完整生产化和正式投产加固不属于本批。

## 3. 范围

### 3.1 本批包含

- 供应商中立的 `EmbeddingPort`、`RerankerPort` 和 `ChatCompletionPort`；
- OpenAI 兼容协议模型适配器、审批端点白名单、模型白名单、超时、并发、限流和费用边界；
- 单轮问题规范化、幂等提交和问答状态机；
- OpenSearch 混合召回、PostgreSQL 最终鉴权、RRF/重排和最小证据包构建；
- 敏感内容检测、脱敏和禁止外发策略；
- 结构化模型输出、引用绑定、逐项支持性检查和严格拒答；
- 问答请求、证据快照、回答、模型调用元数据和评测结果持久化；
- 单轮问答 API、本人结果恢复 API、来源再次鉴权 API；
- Vue 知识问答页面、引用卡片、来源入口、拒答与故障状态；
- 不少于 50 条脱敏黄金案例的版本化数据集、离线评测运行和质量门禁；
- 单元、契约、基础设施集成、纵向验收和 Web 端到端测试；
- 中文运行与评测手册。

### 3.2 本批不包含

- 多轮对话记忆、会话摘要或历史消息自动检索；
- Agent 自主工具调用、联网搜索、代码执行或数据库自由查询；
- 由客户端选择模型、修改系统提示词、关闭脱敏或跳过引用校验；
- 将问答历史重新索引为公司知识；
- 上传原始文件或完整文档给云模型；
- 未经审批的模型端点、自动跨供应商故障转移或动态插件市场；
- 真实敏感客户资料和未经脱敏的生产黄金集；
- 钉钉登录、组织同步、报表生成、完整方案设计工作台和 Word 导出；
- 正式试点标签、生产准入声明、容量压测、灾备演练或渗透测试。

## 4. 总体架构

系统保持模块化单体和既有 Java/Python 边界：

```text
Vue 知识问答页面
        │ HTTPS + Session + CSRF + Idempotency-Key
        ▼
Spring Boot Core API
  ├── qa-domain        问题、证据、回答、引用、拒答和评测模型
  ├── qa-application   鉴权检索、证据筛选、脱敏、生成、校验与审计编排
  ├── retrieval        OpenSearch 召回、RRF、PostgreSQL 最终鉴权
  ├── model-gateway    Embedding / Reranker / ChatCompletion 供应商中立端口
  ├── qa-evaluation    黄金集运行、指标计算和质量门禁
  └── audit            脱敏业务审计与模型调用元数据
        │                  │                         │
        ▼                  ▼                         ▼
   PostgreSQL          OpenSearch             经审批模型网关
   权威事实/ACL         可重建候选投影          最小脱敏证据

Python Parser Worker
  └── 只解析文件，不参与问答，不持有数据库、对象存储或模型凭据
```

浏览器不能提交或覆盖用户身份、ACL 主体、模型名称、模型端点、系统提示词、脱敏策略或检索安全策略。模型只生成候选结构化结果，无权决定是否允许回答；最终结果由 Java 业务规则验证后才能返回。

## 5. 模块职责与稳定边界

### 5.1 `qa-domain`

定义供应商和基础设施无关的值对象与规则：

- `QuestionRequest`：请求 ID、用户 ID、规范化问题、幂等键和接收时间；
- `EvidenceItem`：文档、版本、节点、定位、内容哈希、授权时刻和相关性；
- `EvidenceBundle`：经过最终鉴权、限量和排序的最小证据集合；
- `CandidateAnswer`：模型返回的回答、声明和证据引用 ID；
- `ValidatedAnswer`：通过支持性与定位校验的最终回答；
- `RefusalReason`：标准化的内部拒答原因；
- `EvaluationCase`、`EvaluationRun` 和 `EvaluationMetrics`：版本化评测模型。

领域对象使用不可变集合，拒绝 `null`、未知状态和请求集合之外的引用。拒答与系统故障是不同的领域结果，不以空字符串或通用异常混淆。

### 5.2 `qa-application`

应用服务拥有完整问答编排，按固定次序执行：

1. 从服务端会话解析当前内部用户；
2. 规范化并校验问题，建立幂等请求；
3. 获取服务端解析的当前主体，执行 OpenSearch 混合召回；
4. 使用 PostgreSQL 对候选文档版本做一次批量最终鉴权；
5. 进行 RRF、可选重排、阈值过滤、去重和证据限量；
6. 检查证据是否充分、是否明显冲突；
7. 构建最小证据包，执行敏感内容检测与脱敏；
8. 调用聊天模型获得结构化候选答案；
9. 校验引用 ID、来源定位和每项关键声明的证据支持性；
10. 持久化结果与脱敏审计，返回答案或严格拒答。

任一步骤不得绕过前一步安全边界。最终鉴权失败、返回不完整或权威源异常时整次请求失败关闭，不向后续步骤提供部分候选。

### 5.3 `model-gateway`

提供三个稳定端口：

- `EmbeddingPort.embedQuery`：为规范化查询批量生成向量；
- `RerankerPort.rerank`：接收问题和已授权候选，只返回候选 ID 与相关度；
- `ChatCompletionPort.completeGroundedAnswer`：接收脱敏证据包并返回严格结构化候选答案。

端口不得暴露 OpenAI SDK 类型、HTTP 响应对象或供应商错误码。适配器把外部失败归一为超时、限流、认证、配额、协议非法、内容策略拒绝和临时上游故障。

### 5.4 `qa-evaluation`

评测模块复用生产问答服务的检索、鉴权、脱敏和校验路径，只替换固定的评测身份、问题集和指标收集器。禁止为了提高指标使用另一条绕过生产规则的评测链路。

## 6. 问答数据模型

### 6.1 `qa_request`

保存：

- `request_id`、`user_id`、幂等键哈希；
- 规范化问题的带服务器密钥摘要；
- 当前状态和标准化拒答/失败代码；
- 检索策略、提示词、脱敏策略和模型配置版本；
- 创建、开始、完成时间及乐观锁版本。

默认不保存原始问题。未来如需反馈分析，必须另行审批脱敏留存策略，不能修改默认行为后静默启用。

### 6.2 `qa_evidence_snapshot`

每条记录引用精确的空间、文档、已发布版本、Canonical 节点和来源定位，保存内容哈希、召回/融合/重排分数和采用顺序，不重复保存证据正文。证据快照用于审计“当时使用了什么”，不赋予之后继续读取来源的权限。

### 6.3 `qa_answer`

保存最终回答正文、回答或拒答状态、引用关系、是否降级、模型配置版本、Token 统计和延迟。回答默认只允许发起者和具备问答审计权限的系统管理员读取。系统管理员查看回答正文的行为也必须审计。

### 6.4 `qa_model_call_audit`

保存供应商、审批端点标识、模型、配置版本、请求/响应摘要、Token、耗时、脱敏数量、重试次数和标准化结果码。不得保存凭据、完整提示词、原始问题、证据正文或原始模型响应。

### 6.5 评测表

- `qa_evaluation_dataset`：数据集 ID、名称、版本、状态和审批信息；
- `qa_evaluation_case`：脱敏问题、评测用户夹具、期望证据、禁止文档、是否应拒答和评分规则；
- `qa_evaluation_run`：代码版本、策略版本、模型配置版本、开始/完成时间和总体状态；
- `qa_evaluation_result`：逐案例召回、引用、支持性、拒答、泄露和错误详情。

黄金集内容仍属于受控数据，只允许评测管理员维护和运行。

## 7. 状态机、幂等与生命周期

问答请求状态固定为：

```text
RECEIVED → RETRIEVED → AUTHORIZED → SANITIZED → GENERATED → VALIDATED → ANSWERED
     └────────────── 任一业务底线不满足 ───────────────► REFUSED
     └────────────── 基础设施或上游故障 ──────────────► FAILED
```

- 同一用户、同一幂等键只能创建一个问答请求；载荷不一致时返回幂等冲突。
- 请求只能沿状态机前进，终态不能被迟到的模型响应覆盖。
- 模型临时故障最多重试一次，重试沿用同一请求 ID、配置版本和已确定证据包。
- 重试不得自动切换到未审批模型或扩大证据范围。
- 浏览器连接中断时服务端执行必须受总超时控制，不能无限继续消耗费用。
- 首版不把不同请求关联为会话，也不把历史回答作为下一次提问的证据。
- 证据快照固定到当时的已发布版本；之后文档发布新版本不会改写旧快照。
- 用户打开来源时重新执行当前授权；权限已撤销时拒绝访问，即使旧回答仍存在。
- 问答历史不得进入检索索引或成为知识事实源。

## 8. 检索、证据与严格拒答

### 8.1 检索规则

- 查询先执行 Unicode NFKC、首尾去空白、连续空白折叠和长度限制；
- OpenSearch 使用 BM25 与查询向量双路召回，现有 Java 内核执行 RRF；
- 查询向量不可用时允许降级到 BM25，并记录降级原因；
- 所有候选在重排和模型调用前必须通过 PostgreSQL 最终鉴权；
- Reranker 只接收已授权片段，不得看到被最终鉴权剔除的内容；
- Reranker 不可用时可以使用 RRF 顺序，但采用更严格的最低证据阈值；
- 相同文档/节点去重，限制每个文档和总证据数量，避免单一来源垄断上下文。

### 8.2 证据包

证据包只包含回答所需的最少字段：不可猜测的证据 ID、脱敏文本、文档显示名、版本、来源定位类型和定位值。不得包含内部对象存储路径、ACL、用户信息、审计信息或整份文档。

### 8.3 严格拒答条件

出现下列任一情况时不得输出推测性答案：

- 最终鉴权后没有证据；
- 证据相关性、数量或覆盖度低于策略阈值；
- 关键事实在证据间明显冲突且无法安全消解；
- 证据无法在外发限制内安全脱敏；
- 脱敏器异常或模型调用失败；
- 模型响应不是约定结构；
- 模型引用未知、未提供、已失效或无法定位的证据；
- 关键声明缺少逐项支持关系；
- 生成内容包含证据包之外可识别的事实扩展；
- 任一最终安全校验异常。

对外拒答原因保持有限且可理解，例如“现有知识不足”“证据存在冲突”“内容无法安全处理”。不得向用户透露是否存在因权限不足被过滤的文档。

## 9. 敏感内容与云端外发控制

`SensitiveContentSanitizer` 在模型调用前执行，至少覆盖：

- 手机号、身份证号、邮箱和可配置账号标识；
- 常见访问密钥、令牌、私钥和连接串特征；
- 公司配置的业务敏感词、项目代号和禁止外发分类；
- 结构化表格中可能形成批量个人信息的列。

检测结果按规则执行掩码、删除片段或整次拒绝。脱敏后重新计算证据长度和有效性；若脱敏导致证据不足则拒答。系统只允许访问配置中的审批端点标识，生产启动时解析并校验 HTTPS、主机白名单和模型白名单，禁止用户输入任意 URL。

模型凭据只通过仓库外密钥注入，不能进入数据库、前端配置、日志、镜像或 Git。出站代理、DNS 和网络策略属于部署层第二道限制，应用白名单不能替代网络出站控制。

## 10. 模型协议与提示词契约

### 10.1 结构化输入

聊天端口接收：规范化问题、编号证据包、回答语言、最大输出长度和策略版本。系统提示词由服务端版本化模板生成，要求只使用证据、逐项引用、冲突时拒答并返回固定 JSON Schema。

### 10.2 结构化输出

候选回答至少包含：

- `decision`：`ANSWER` 或 `REFUSE`；
- `answer`：回答正文；
- `claims`：关键声明列表；
- 每个声明对应的 `evidenceIds`；
- 模型建议的拒答类别。

业务层不信任模型的 `decision` 或引用。它必须独立检查 Schema、证据 ID 闭包、来源定位、文本支持性、最大长度和禁止模式。模型建议拒答可以被接受，但模型建议回答只有通过所有校验后才能成为最终答案。

## 11. API 设计

### 11.1 提交问题

`POST /api/qa/questions`

- 使用服务端 Session 与 CSRF；
- 必须携带 `Idempotency-Key`；
- 请求体只包含问题文本；
- 客户端不能指定用户、主体、模型、端点、提示词或安全策略；
- 首版同步等待结果，但受应用总超时控制；
- 返回回答、拒答或标准化故障响应及 `requestId`。

### 11.2 恢复结果

`GET /api/qa/questions/{requestId}`

只允许发起者或具备专门问答审计权限的系统管理员读取。对不存在和无权读取统一返回不泄露资源存在性的响应。

### 11.3 查看来源

`GET /api/qa/questions/{requestId}/sources/{evidenceId}`

服务端验证请求归属、证据确属该回答，并根据当前用户、当前发布状态和当前 ACL 再次鉴权。通过后复用既有来源定位/下载能力；失败时不得返回标题、版本或定位元数据。

### 11.4 评测管理

黄金集维护、运行和结果接口置于独立管理路径，只授予系统管理员中的评测权限。评测请求不能接受任意用户 ID 或绕过授权的参数。

## 12. Web 交互

Vue 新增“知识问答”页面：

- 输入区明确说明只依据已发布且本人有权访问的知识回答；
- 提交期间禁用重复操作，并使用客户端生成的幂等键；
- 回答正文中的关键结论显示引用编号；
- 引用卡片显示文档名、版本和页码、章节、幻灯片、单元格或图片区域等定位；
- “查看来源”始终调用服务端再次鉴权接口；
- 明确标记仅全文检索或未重排等降级状态；
- 业务拒答与系统故障使用不同状态和行动建议；
- 不展示被权限过滤的候选数量、名称或拒绝原因；
- 不提供模型选择、提示词编辑、关闭引用或关闭脱敏的入口。

页面刷新后可使用 `requestId` 恢复本人结果，但不提供跨请求的多轮上下文。无障碍状态文本、加载状态、空状态、窄屏引用布局和长文本溢出必须纳入 UI 验收。

## 13. 故障、降级与费用控制

| 情况 | 行为 |
|---|---|
| Embedding 超时或未配置 | 降级 BM25，记录原因 |
| Reranker 临时不可用 | 使用 RRF 顺序并提高最低证据阈值 |
| PostgreSQL 最终鉴权异常 | 整次失败关闭 |
| 脱敏器异常 | 禁止外发并失败关闭 |
| 证据超出上下文限制 | 按确定性策略缩减；仍不满足则拒答 |
| Chat 模型超时、限流或协议非法 | 最多一次受控重试；仍失败则 `FAILED` |
| 引用或支持性校验失败 | `REFUSED`，不修补模型内容 |
| 费用日限额或并发上限达到 | 拒绝新模型调用并返回可重试故障 |

模型使用策略按用途绑定审批配置。生产环境必须配置单请求最大输入/输出 Token、总超时、连接超时、并发上限、用户级速率限制和部署级日费用上限。费用限制触发不能自动切换更昂贵或未审批的模型。

## 14. 测试策略

### 14.1 领域与应用测试

- 问题规范化、长度边界和摘要稳定性；
- 状态机、终态保护、幂等冲突和迟到响应；
- 证据阈值、冲突检测、去重和最小证据包；
- 严格拒答的每个条件；
- 引用闭包、逐项支持性和来源定位校验；
- 费用、并发、超时和一次重试策略；
- 使用固定假模型，不依赖外部 API。

### 14.2 模型适配器契约测试

使用 Mock HTTP Server 验证 OpenAI 兼容请求与响应、认证头保护、超时、限流、非法 JSON、未知证据 ID、Token 统计和日志脱敏。测试必须断言凭据、原文和完整提示词不会进入日志或持久化审计。

### 14.3 基础设施集成测试

使用真实 PostgreSQL 和 OpenSearch Testcontainers 验证：

- 混合召回后批量最终鉴权；
- 未授权候选在模型调用前被剔除；
- 检索过程中撤权不会泄露；
- 旧回答来源在撤权后无法再次打开；
- 问答、证据快照、回答与审计的事务一致性；
- 并发相同幂等键只产生一次计费模型调用。

### 14.4 纵向验收

覆盖管理员创建并发布知识、有权用户获得带引用回答、无权用户看不到内容、撤权立即生效、证据不足、证据冲突、敏感内容、模型故障、来源查看和 Web 状态。验收必须捕获模型请求体并证明其中不存在未授权片段。

### 14.5 Web 测试

Vue 组件和 Playwright 覆盖提交、防重复、回答、引用、降级、拒答、故障、刷新恢复、来源再次鉴权以及窄屏/长文本布局。

## 15. 黄金集与质量门禁

首版建立不少于 50 条脱敏黄金案例，覆盖：

- 普通单文档与跨文档问答；
- Word/PDF 页码、PPT 幻灯片、Excel 单元格、Markdown 标题和 PNG OCR 定位；
- 同义表达、缩写、低相关问题和证据冲突；
- 应拒答问题；
- 用户无权访问相关资料的权限陷阱；
- 明确列出的禁止文档和禁止节点。

内部受控测试发布门槛：

| 指标 | 底线 |
|---|---:|
| 权限越权或禁止文档泄露 | 0 |
| 引用可定位且当前有效 | 100% |
| Recall@10 | ≥ 85% |
| 有答案场景的证据支持率 | ≥ 90% |
| 应拒答场景的正确拒答率 | ≥ 90% |

权限泄露和引用无效是硬失败，不能被平均分掩盖。数据集、代码、检索策略、提示词、脱敏策略和模型配置均需记录版本，确保结果可追踪。首版门槛用于内部试运行，积累真实脱敏反馈后只能通过评审调整，不能为通过构建临时降低。

## 16. 可观测性与审计

指标至少包括：请求量、回答/拒答/失败率、各阶段延迟、召回数量、鉴权剔除数量的内部聚合、降级率、模型错误类别、Token、估算费用、脱敏命中数量和质量门禁结果。业务日志只记录请求 ID、内部错误码和安全摘要，不记录问题正文、证据正文、回答正文、提示词或凭据。

链路追踪使用请求 ID 贯穿 API、检索、鉴权、脱敏和模型调用，但不得把敏感载荷作为 Span 属性。对模型配置、提示词版本、脱敏策略和黄金集的变更必须记录管理员、时间和版本。

## 17. 安全与隐私验收

- 所有问答和来源接口使用现有 Session、CSRF 和统一错误边界；
- 所有身份和主体关系由服务端解析；
- PostgreSQL 最终鉴权发生在模型调用前，来源访问时再次鉴权；
- 生产只允许审批端点和模型，凭据来自仓库外密钥；
- 未授权内容、原始文件、完整文档、ACL 和身份信息不外发；
- 脱敏或鉴权异常时失败关闭；
- 日志、数据库审计和追踪不保存禁止内容；
- 普通用户不能读取他人问题或回答；
- 问答历史不成为知识资产或检索语料；
- 自动化测试覆盖撤权竞态、未知引用、提示词注入式文档内容和敏感数据外发阻断。

文档中的指令性文本一律视为不可信数据。系统提示词必须明确证据内容不能改变系统规则、调用工具或要求泄露其他上下文；业务层仍以结构化校验和授权边界作为最终保障。

## 18. 完成标准与后续门槛

本批完成必须同时满足：

- 供应商中立端口和 OpenAI 兼容适配器落地，生产配置默认安全关闭；
- 单轮问答 API/UI 完成，答案具备逐项、可再次鉴权的来源引用；
- 严格拒答、脱敏、幂等、超时、限流、费用和审计边界均有自动化验证；
- 未授权内容进入模型请求的测试结果为零；
- 不少于 50 条脱敏黄金案例和全部质量门禁自动运行；
- Java、Vue、Python、Compose、真实 PostgreSQL/OpenSearch 纵向验收全部通过；
- 中文运行手册覆盖配置、密钥注入、降级、故障、费用、评测和回滚；
- 不上传真实敏感资料，不创建 `pilot-retrieval-v1` 或其他正式试点标签。

完成本批后，系统可进入内部受控的可信问答测试，但仍不能宣称生产准入。后续至少还需完成真实审批模型网关联调、真实脱敏黄金集、容量和费用验证、备份恢复、渗透测试、值班告警及正式审批。钉钉、报表和方案工作台仍按独立批次实施。
