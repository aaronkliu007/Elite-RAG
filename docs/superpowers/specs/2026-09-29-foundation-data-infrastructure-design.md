# 知识底座数据基础设施设计

**日期：** 2026-09-29
**状态：** 已批准
**适用范围：** 知识底座 PostgreSQL、Flyway、MinIO 与生产仓储适配器第一批

## 1. 目标与背景

当前仓库已经具备组织同步、ACL、不可变文档版本、安全上传、可恢复入库、解析结果、审计、可信检索和方案工作台的基础设施中立业务内核，但核心流程仍主要通过内存端口验收。现阶段不能证明数据库约束、并发领取、跨仓储事务回滚和对象存储补偿在真实基础设施中成立。

本批目标是把知识底座的第一条生产数据链路落到 PostgreSQL 和 MinIO：授权用户能够在本地集成环境完成组织与权限准备、文档版本创建、Blob 保存、入库任务领取、解析结果保存、人工发布、授权读取和审计，并由真实数据库测试证明关键写入原子提交或完整回滚。

本批服务于研发和后续联调，不代表系统已经具备真实客户数据或试点投产资格。

## 2. 已确认约束

- 固定工作目录为 `E:\git\_repo\Elite-RAG`。
- 数据留在内网；本批不调用云模型，不接入真实客户资料。
- Java 21 / Spring Boot 是业务事实和事务边界的唯一所有者。
- PostgreSQL 是权威数据源；MinIO 只保存不可变原始文件。
- Python Worker 不持有数据库或 MinIO 凭据。
- 权限默认拒绝，未授权和资源不存在对外保持相同语义。
- 数据访问采用 Flyway + PostgreSQL + Spring `JdbcClient` 显式 SQL，不使用领域对象直接映射 JPA Entity，也不把聚合整体保存为 JSONB。
- 本批不创建任何试点标签，不宣称可投产。

### 3.1 包含

- README 与中文运行手册更新。

### 3.2 不包含

- OpenSearch、Embedding、Reranker、索引投影和检索质量黄金集；
- 可信检索与方案工作台的生产数据库表和仓储适配器；

- 新业务 API、Vue 页面或 Word 导出；

## 4. 架构

```text
领域服务与端口
    │
    ├── PostgreSQL / JdbcClient 适配器
    │     ├── 组织与会话
    │     ├── 知识空间、文档与版本
    │     ├── ACL
    │     ├── 入库任务与解析结果
    │     ├── Blob 预留与清理候选
    │     └── 只追加审计
    │
    └── MinIO BlobStore 适配器
          ├── SHA-256 内容寻址
          ├── 幂等写入
          └── 失败后的延迟清理登记
```

基础设施代码放在独立适配器包中，只依赖既有领域端口。领域对象不得依赖 Spring JDBC、数据库行模型、MinIO SDK 或配置类型。JdbcClient 适配器负责显式 SQL、行映射、约束异常翻译和乐观锁；应用服务现有的 `@Transactional` 继续定义业务事务边界。

## 5. PostgreSQL 数据模型

### 5.1 身份与组织

- `app_user`：内部 UUID、钉钉外部 ID、显示名、启用状态、会话版本、创建与更新时间；外部 ID 唯一。
- `org_unit`：内部 UUID、外部 ID、父部门 ID、名称、启用状态、创建与更新时间；外部 ID 唯一，父部门使用自引用外键。
- `org_membership`：用户与部门的多对多隶属关系及快照时间；联合主键防止重复。

首次发现外部用户或部门时创建兼容 UUIDv7 的内部 ID；后续同步按外部 ID 保持映射稳定。当前钉钉快照只提供部门隶属关系，角色和项目组集合在本批保持为空，不提前创建无数据来源的表。

### 5.2 知识资产

- `knowledge_space`：空间 ID、名称、创建人、创建时间。
- `document`：文档 ID、空间 ID、标题、当前发布版本 ID、归档标志和乐观锁 revision。
- `document_version`：版本 ID、文档 ID、版本号、源 Blob ID、文档状态、解析状态、创建人与状态变更信息。
- `active_blob_reservation`：空间、SHA-256、文档和版本绑定；`(space_id, sha256)` 唯一，作为并发上传去重事实。

文档版本号在单个文档内唯一。当前发布版本必须属于同一文档。归档操作移除对应活跃 Blob 预留，但不删除历史版本或 MinIO 对象。

### 5.3 权限

- `acl_entry`：空间 ID、可选文档 ID、主体类型、主体 ID、生效截止时间、撤销时间、创建与更新时间。

空间授权与文档授权共用一张表，通过检查约束保证作用域一致：空间级记录不得带文档 ID，文档级记录必须带文档 ID。有效授权的唯一索引防止同一作用域和主体重复生效。读取判定以当前组织隶属、空间授权、文档收紧授权、发布状态和有效期一次查询得出。

### 5.4 入库与解析

- `ingestion_job`：任务 ID、文档/版本 ID、发起人、Blob、文件元数据、状态、尝试次数、下一次尝试时间、租约 token/worker/截止时间、固定错误码和时间戳。
- `canonical_document`：文档版本 ID、源文件名、媒体类型、页数、解析完成时间。
- `canonical_node`：版本 ID、节点 ID、类型、正文、父节点、页码、定位框、表格单元格、置信度和稳定顺序。

定位框和表格单元格使用受契约验证的 JSONB；正文保持普通文本列以支持后续投影，不把整个 CanonicalDocument 保存为单个 JSONB。`(version_id, node_id)` 唯一，父子关系在应用层完成完整性校验后写入。

### 5.5 审计与对象补偿

- `audit_event`：事件 ID、行为人、动作、资源类型、资源 ID、结果、白名单元数据 JSONB 和发生时间，只允许追加。
- `blob_cleanup_candidate`：存储桶、SHA-256、对象键、登记时间、状态和最后检查时间；`(bucket, object_key)` 唯一。

数据库运行账号不获得更新或删除 `audit_event` 的应用路径；代码只提供 `append` 端口。Blob 清理候选不等于删除授权，未来回收器必须再次确认无文档版本引用和活跃预留。

## 6. 关键事务与并发语义

### 6.1 组织同步

完整快照在一个事务中批量 upsert 部门和用户、重建隶属关系、停用缺失或禁用用户并提升会话版本。不完整快照在进入适配器前拒绝；数据库失败时保留上一份完整快照。

### 6.2 文档与上传

文档聚合、版本、活跃 Blob 预留和成功审计在同一数据库事务中提交。`DocumentRepository.replace` 使用 `WHERE id = ? AND revision = ?`，更新行数不是 1 时抛出固定并发异常。`active_blob_reservation` 唯一约束保证两个并发请求不能在同一空间为相同 SHA-256 建立两个活跃版本。

MinIO 对象先按内容寻址幂等写入。若随后数据库事务失败，只为本次新建对象登记 `blob_cleanup_candidate`；不得在请求线程直接删除对象。

### 6.3 入库任务

任务领取使用单条 CTE/UPDATE：选择最早可执行的排队任务或租约已过期任务，使用 `FOR UPDATE SKIP LOCKED`，原子递增尝试次数并写入新 token、worker 和截止时间。完成、重试或失败都必须匹配当前 lease token；旧 token 更新行数为零并返回固定租约冲突。

入库完成在同一事务中替换 Canonical 文档和节点、推进文档版本到待评审、完成任务并追加 PARSE 成功审计。任一写入失败全部回滚。可重试错误只更新时间和下一次尝试时间；不可重试或达到上限时同时标记文档解析失败。

### 6.4 ACL 与审计

ACL 授权或撤销与审计同事务提交。审计写入失败时业务写操作失败，不允许静默跳过审计。读取审计是否允许降级仍需安全负责人批准，本批保持失败关闭。

## 7. MinIO 与对象语义

- 固定存储桶为配置项，本地默认创建 `rag-documents`；
- 对象键为 `sha256/<前两位>/<完整 SHA-256>`，不含原始文件名；
- `putIfAbsent` 通过对象存在性检查和条件写语义保证幂等；并发竞争后必须核对对象长度和媒体类型，冲突时失败而不是覆盖；
- 对象不可变，应用不提供覆盖接口；
- readiness 检查存储桶存在和受控探针能力，不读写业务对象；
- 本批不实现物理清理 Worker，只持久化清理候选和引用复核查询。

## 8. 配置、安全与错误边界

- `application.yml` 只保存非敏感通用参数；`application-local.yml` 启用 PostgreSQL、Flyway 和 MinIO 适配器。
- Testcontainers 动态注入地址与临时凭据；生产凭据只能来自环境变量或密钥系统。
- 数据库迁移账号与运行账号分离；运行账号不能修改 Schema。
- PostgreSQL 与 MinIO 的 Compose 端口只绑定本机或明确的内网接口。
- Flyway 校验失败、迁移缺失或校验和变化时 Core API 拒绝启动。
- 数据库或 MinIO 不可用时 readiness 失败，liveness 不因暂时依赖故障误杀 JVM。
- 驱动异常、SQL、表名、连接串和供应商错误不得直接返回 API 或写入审计。
- 日志不得记录正文、节点文本、文件字节、未脱敏文件名、Token、Cookie、数据库或 MinIO 密钥。
- 约束冲突、乐观锁失败和租约冲突转换为稳定业务异常；未知持久化错误保留服务端关联 ID，对外使用固定错误码。

## 9. 健康检查

- 存活检查只证明 JVM 可响应。
- 就绪检查确认 Flyway 版本正确、数据库可执行只读探针、MinIO 存储桶存在并可完成受控探针。
- readiness 任一分项失败即从流量中摘除，但不得修改业务数据或触发自动迁移回滚。
- Compose 对 PostgreSQL、MinIO 和建桶任务配置明确健康条件；Core API 必须等待前置依赖就绪。

## 10. 测试策略

### 10.1 迁移契约

- 空 PostgreSQL 由 Flyway 创建全部表、索引、外键、检查约束和唯一约束；
- 重启后迁移版本稳定；
- 缺失、乱序或校验和变化时启动失败；
- 运行账号修改 Schema 被拒绝。

### 10.2 仓储契约

每个 JdbcClient 适配器验证完整往返映射、null/枚举/时间/UUID/JSONB 精度、约束异常翻译和真实 revision 乐观锁。测试不得用 H2 替代 PostgreSQL。

### 10.3 并发

- 同空间同 SHA-256 并发上传只有一个活跃预留；
- 相同 revision 并发更新文档只有一个成功；
- 多 Worker 不会领取同一任务；
- 过期租约可被新 Worker 接管，旧 token 不能完成任务。

### 10.4 故障注入

分别在解析正文、节点、文档状态、任务状态和审计写入处制造失败，断言相关表全部回滚。ACL 变更与审计、组织对账与会话停用执行相同原子性验证。

### 10.5 MinIO

- 相同 SHA-256 重复写入不覆盖、不生成第二对象；
- 对象键不包含文件名；
- 数据库失败后生成清理候选；
- 引用或预留存在时，引用复核查询必须返回“不可清理”；
- 存储桶缺失或不可写时 readiness 失败。

### 10.6 纵向验收与回归

新增真实 PostgreSQL 纵向验收，覆盖“组织与会话—ACL—上传—入库—解析结果—待评审—发布—授权读取—审计”。同时运行现有 Java、Python、Vue 和 Playwright 全量门禁，以及 `docker compose config --quiet`。
