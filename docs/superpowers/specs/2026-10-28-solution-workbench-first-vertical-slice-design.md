# 方案工作台生产化：第一条纵向闭环设计

**日期：** 2026-10-28

**状态：** 已批准，待实施

**工作目录：** `<项目根目录>`

## 1. 目标与边界

面向公司内部员工，将已有的方案工作台纯 Java 业务内核接入 PostgreSQL、Spring HTTP API 和 Vue 页面。员工可以在一个知识空间内创建方案，录入及修订有来源的需求，人工确认需求，再编写及确认大纲。应用重启后状态可恢复，并发编辑、撤权和无权访问均有明确结果。这为后续分章生成建立真实的持久化人工门禁。

首批不交付分章生成、风险确认、定稿、Word 导出或钉钉同步；这些属于后续闭环。继续保持一家企业独立部署一套实例，不引入 SaaS 多租户。受控测试可以使用虚构数据；生产准入另行验收。

## 2. 考虑过的路径

| 路径 | 收益 | 代价 |
|---|---|---|
| A：按业务纵向闭环交付 | 每批形成可操作、可验收的完整业务路径 | 第一批需要同时接入数据库、API 和页面 |
| B：先完成全部数据库适配器 | 基础设施改动集中 | 用户长时间无法操作和验证业务流程 |
| C：先用内存实现页面 | 可更快展示界面 | 重启丢数据，随后需重做页面所依赖的行为 |

**已选择 A。** 先交付需求和大纲的人工确认闭环，再做分章生成与核验，最后做来源查看和 Word 导出。保留已经实现的领域内核，基础设施通过端口适配。

## 3. 架构与数据流

Vue 通过现有 Session 调用 Spring Web 层。Web 层只处理身份、请求校验和 DTO；应用层负责数据库事务、幂等和视图组装；现有 `SolutionWorkbenchService` 负责领域状态转移。PostgreSQL 保存方案及不可变版本，现有审计组件在相同事务内记录成功变更。OpenSearch 不保存方案业务状态。

新增 Flyway `V008__solution_workbench.sql`。表包括：

- `solution`：空间、名称、创建信息、阶段、当前需求和大纲版本指针、确认信息、聚合 `revision`、方案修订号；
- `solution_requirement_version`、`solution_requirement_item`、`solution_requirement_source`：不可变需求版本、结构化条目和版本化来源；
- `solution_outline_version`、`solution_outline_node`、`solution_outline_node_risk`：不可变大纲版本、章节和风险类型；
- `solution_command_idempotency`：作用域、客户端键、规范化请求摘要、完成结果引用和状态，不保存正文。现有通用幂等表保存完整响应体，不适合包含客户需求的方案操作；本表只保存不含正文的结果引用。

新增方案名称，限制长度并拒绝空白；名称仅用于界面和列表，不把客户正文复制进名称。需求和大纲版本只插入，`(solution_id, number)` 唯一。聚合指针、来源版本和确认对象必须归属同一方案或空间；由事务内校验和外键共同保证。来源定位只接受现有页、幻灯片、表格、Markdown 四种白名单结构；服务端验证文档版本真实、与方案空间一致且操作者当前可读。未发布、已撤权或无权来源不能成为已知需求的依据；来源失效时确认及后续生成门禁失败关闭。

聚合更新用 `WHERE id = ? AND revision = ?`；影响行数不是 1 时返回冲突。每个写操作将不可变版本插入、聚合指针移动、成功审计及幂等结果记录放在一个数据库事务内。事务失败时四者均回滚。避免把未提交结果缓存为已完成幂等响应。

## 4. HTTP 契约

```text
POST /api/v1/knowledge-spaces/{spaceId}/solutions
GET  /api/v1/knowledge-spaces/{spaceId}/solutions
GET  /api/v1/solutions/{solutionId}
PUT  /api/v1/solutions/{solutionId}/requirements
POST /api/v1/solutions/{solutionId}/requirements/{versionId}/confirm
PUT  /api/v1/solutions/{solutionId}/outline
POST /api/v1/solutions/{solutionId}/outline/{versionId}/confirm
```

列表按当前空间和当前权限过滤，使用稳定排序与有界分页。详情在每次读取时重新验证空间访问，加载当前版本及确认信息。任何版本级读取都必须先验证其方案归属；不开放仅凭版本 UUID 猜测读取内容的接口。DTO 返回名称、空间、阶段、聚合版本、当前需求/大纲版本、确认人和时间、`allowedActions`。不返回内部 ACL 主体集合或审计元数据。

写请求要求 `Idempotency-Key`、`expectedRevision`；修订要求非空修改原因。创建时使用固定的初始原因。操作者、ID、时间和版本号均由服务端给出。幂等键按操作者、资源、动作和客户端键限定作用域；相同键及相同规范化请求摘要返回首次已提交结果，不同摘要返回 `409 IDEMPOTENCY_CONFLICT`。进行中并发请求由唯一约束与行级锁串行化，失败事务可安全重试。重放时按完成结果引用重建首次提交的响应，逐项复核操作者当前空间和来源权限；若空间已撤权则返回隐藏式 `404`，若历史来源已撤权则返回不含正文的 `409 IDEMPOTENT_RESULT_UNAVAILABLE`，不得回传历史正文或以当前版本冒充原结果。

错误：非法输入 `400`，未登录 `401`，不存在或无权查看统一 `404`，版本或幂等冲突 `409`，业务门禁不满足 `422`，权威权限源不可用 `503` 并失败关闭。错误和业务日志不含需求正文、来源内容、Cookie、模型输入或密钥。

## 5. 权限与人工门禁

首版由现有空间角色映射方案动作：`EDITOR`、`SPACE_ADMIN`、系统管理员可创建和编辑；`REVIEWER_PUBLISHER`、`SPACE_ADMIN`、系统管理员可确认。所有方案动作先要求当前有效空间读取权限，包括系统管理员；未加入空间的系统管理员不能直接查看或修改方案，应通过现有成员管理流程获得权限。新增独立 `EDIT_OUTLINE` 动作，编辑不再借用 `CONFIRM_OUTLINE`。后端逐次鉴权，`allowedActions` 仅作为 UI 提示。列表不可泄漏无权方案的名称和存在性。

默认由不同人员完成当前需求或大纲的编辑与确认。实例级 `SolutionReviewPolicy` 可按企业治理制度调整，运行时请求不能覆盖策略。确认仅绑定当前准确版本；修改需求立即撤销需求和大纲确认及后续资格，修改大纲撤销大纲确认及后续资格。确认与版本写入也受乐观锁保护。来源后来撤权时保留历史确认记录供审计，但读取时动态显示“确认已失效”；后续生成门禁重新验证来源，失效则拒绝，不依赖异步撤权事件改写历史确认。

## 6. 页面与交互

导航加入“方案工作台”。空间内方案列表有名称、阶段、更新时间和创建入口；方案详情分为“需求”和“大纲”两个连续步骤，并显示当前版本、确认状态及确认人。需求编辑以结构化条目呈现分类、文字和来源定位；已知事实必须选择已发布且当前有权的文档版本及位置，未知项明确标为 `UNKNOWN`。大纲编辑按顺序展示章节标题、层级、目标、检索提示和风险类型；必填章节清晰标记。

只显示 `allowedActions` 允许的操作，但提交后仍由后端再次鉴权。保存与确认分开操作，确认前展示准确版本号。网络失败时保留当前表单；离开未保存页面时提示；保存成功后刷新当前版本与权限。遇到 `409` 显示并发冲突并提供重新加载，绝不自动覆盖用户文本。加载、空列表、错误、无权和窄屏状态均有可读提示；长文本不挤压主操作区，键盘可完成主要操作。

## 7. 验收与后续边界

先写失败测试，再实现：领域权限映射、不可变版本、事务原子性、幂等并发及重放撤权、跨空间隐藏、来源有效性、乐观锁、编辑者与确认者分离、需求修改使大纲确认失效。使用真实 PostgreSQL Testcontainers 验证迁移和重启恢复；API 集成测试验证 Session、状态码及无权内容不外泄；Vue 单元和 Playwright 端到端测试覆盖创建、编辑、确认、并发冲突与窄屏可用性。运行现有 Java、Vue、Python 回归及仓库统一门禁，记录无法运行的外部环境项目。

本批完成的判据是员工能从页面创建、修订和确认需求与大纲，重启后仍能恢复；无权用户无法获得方案名称、正文或来源；所有安全和事务测试通过。不得因此声明方案工作台已投产或创建试点标签。下一批才装配可恢复生成任务、模型网关和章节核验；最终批次交付安全 Word 导出及业务试点验收。

## 8. 实施者可决定的细节

分页大小、具体 Vue 组件拆分、SQL 索引和 DTO 类名可按仓库现有模式选择，但必须遵守以上权限、事务、版本与错误契约。若现有 `Solution` 聚合无法无损从数据库重建，应先增加受约束的重建工厂及往返测试，不得用反射或可变字段绕过领域不变量。
