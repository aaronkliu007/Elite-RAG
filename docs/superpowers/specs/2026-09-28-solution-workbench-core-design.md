# 基础设施中立的方案工作台业务内核设计

- 状态：待用户书面审阅
- 日期：2026-09-28
- 前置能力：知识底座业务边界、`RetrievalService` 可信检索内核
- 适用阶段：数据库、搜索引擎、模型供应商和前端尚未接入前的业务内核阶段

## 1. 背景与目标

云基华海首期优先建设“方案设计与评审工作台”，目标闭环为：

`客户需求确认 -> 方案大纲确认 -> 分章检索与生成 -> 引用核验 -> 风险确认 -> 人工定稿`

当前仓库已经具备知识生命周期、ACL、统一解析和基础设施中立的可信检索内核，但尚未具备 PostgreSQL、OpenSearch、真实云模型、生产 HTTP API 和 Word 导出。现阶段不能实施完整方案工作台，也不能创建 `pilot-retrieval-v1` 或 `pilot-workbench-v1`。

本设计先交付可长期保留的纯 Java 业务内核，用内存端口证明方案版本、人工门禁、分章生成、幂等恢复、引用支持性和高风险事实确认。后续基础设施只实现端口适配器，不重写核心业务规则。

## 2. 本批范围

### 2.1 范围内

- 方案、需求、大纲、章节的不可变版本和当前版本指针；
- 需求确认、大纲确认、章节采纳、风险确认和定稿门禁；
- 供应商中立的结构化模型请求与响应契约；
- 调用现有 `RetrievalService` 的分章检索编排；
- 可恢复、可取消、受版本栅栏保护的章节生成状态机；
- Evidence ID 白名单、引用支持性与高风险事实规则；
- 定稿前 Evidence 当前访问权限复核；
- 幂等生成、费用摘要和无正文审计；
- 纯内存纵向验收和中文运行说明。

### 2.2 范围外

- PostgreSQL、Flyway、任务表、消息队列和分布式锁；
- HTTP Controller、OpenAPI、Vue、TipTap 和实时协作；
- Spring AI、真实云模型 SDK、密钥、出网和生产模型计费；
- Word 导出、对象存储和下载接口；
- 生产 Prompt 内容、真实客户资料和检索/生成黄金集；
- `pilot-retrieval-v1`、`pilot-workbench-v1` 或其他试点标签。

## 3. 设计原则

1. **人工门禁优先**：未确认的需求和大纲不能进入长文本生成。
2. **版本而非覆盖**：需求、大纲、章节和评审决定都以不可变版本表达。
3. **旧任务不能胜出**：所有异步结果都必须通过需求、大纲和章节基线版本栅栏。
4. **证据不足就停止**：证据不足时不调用模型，不生成看似完整但不可追溯的内容。
5. **生成结果不可信**：模型输出必须经过结构、引用和风险核验，且只产生待采纳版本。
6. **高风险必须有人负责**：金额、工期、性能、客户事实、公司能力和法律承诺必须有证据，并按策略取得人工确认。
7. **端口隔离基础设施**：领域对象不依赖 Spring、数据库实体、HTTP DTO、模型 SDK 或具体供应商。
8. **默认失败关闭**：权限、引用复核或关键核验异常时不得定稿。

## 4. 模块与依赖边界

新增包根：

```text
com.yunjihai.rag.solution
├── domain          方案、版本、状态、引用和风险值对象
├── generation      分章检索、生成、幂等与恢复编排
├── verification    确定性引用核验、风险规则和定稿门禁
└── port            模型、权限、Evidence 复核、时钟外的基础设施端口
```

唯一允许的主要依赖方向为：

```text
SolutionWorkbenchService
    ├── solution domain
    ├── RetrievalService             已有可信检索入口
    ├── SolutionModelPort            供应商中立模型端口
    ├── CitationVerificationPort     可选语义支持性核验
    ├── EvidenceAccessPort           定稿前 Evidence 当前权限复核
    ├── SolutionAuthorizationPort    工作台动作授权
    ├── Clock 与 ID 端口
    └── AuditSink                    现有脱敏审计边界
```

可信检索模块不得反向依赖方案模块。模型端口不得自行查询数据库、放宽检索权限或读取方案聚合之外的内容。

## 5. 核心领域模型

### 5.1 `Solution`

`Solution` 是聚合根，至少包含：

- `solutionId`、`spaceId`、创建人和创建时间；
- 当前需求版本 ID；
- 当前大纲版本 ID；
- 当前方案修订号和乐观版本号；
- 各章节当前采纳版本指针；
- 当前流程阶段；
- 定稿版本 ID（若存在）。

聚合根只保存当前指针和门禁状态，不把历史版本复制进可变字段。任何保存操作都携带期望乐观版本；冲突必须显式失败，不能最后写入者静默覆盖。

### 5.2 `RequirementVersion`

不可变需求版本包含：

- 目标、范围、约束和交付物；
- 干系人、日期、未知项和风险；
- 每个事实对应的客户资料定位；
- 创建人、创建时间和修改原因；
- 确认人、确认时间（确认后生成新的确认记录，不修改正文）。

资料定位是供应商中立的来源引用，不允许用文件路径或对象存储 URL 代替稳定定位。

### 5.3 `OutlineVersion`

不可变大纲由有序 `OutlineNode` 构成。节点至少包含：

- 稳定 `sectionId`；
- 标题、层级和顺序；
- 是否必填；
- 章节目标；
- 检索提示；
- 风险规则集合。

节点 ID 不得重复，层级必须有界，必填节点不得删除。确认只对准确的大纲版本生效。

### 5.4 `SectionVersion`

不可变章节版本包含：

- `sectionVersionId`、`sectionId`；
- 来源类型：`MODEL_DRAFT | HUMAN_EDIT | ADOPTED`；
- 正文和结构化 `Claim` 集合；
- Evidence ID 集合；
- 基于的需求、大纲和前序章节版本；
- 创建人/模型、时间和父版本；
- 核验摘要。

模型成功只创建 `MODEL_DRAFT`。人工明确采纳后生成 `ADOPTED` 版本并移动当前指针；单章重生成不得自动替换已采纳版本。

### 5.5 `Claim` 与引用

事实性陈述表示为 `Claim`，包含稳定 ID、陈述文本、风险类型和一个或多个 Evidence ID。模型只能引用本次请求白名单内的 Evidence ID。

未知 ID、重复声明 ID、缺失必需引用、空陈述或对 Evidence 来源字段的改写均使整次模型结果非法。非法结果不得部分采用。

### 5.6 `GenerationAttempt`

每次生成尝试包含：

- 幂等键；
- 方案、需求、大纲、章节和基线章节版本；
- 检索请求 ID 和最终 Evidence ID；
- Prompt 名称与版本；
- 模型逻辑标识；
- 状态、尝试次数和截止时间；
- Token、费用、延迟等非正文摘要；
- 结果章节版本 ID或规范化失败代码。

相同幂等键必须解析到同一逻辑尝试。重复执行不得新增章节版本、费用记录或 Evidence 绑定。

## 6. 流程状态与版本失效

方案主流程：

```text
REQUIREMENTS_DRAFT
  -> REQUIREMENTS_CONFIRMED
  -> OUTLINE_DRAFT
  -> OUTLINE_CONFIRMED
  -> GENERATING
  -> IN_REVIEW
  -> READY_TO_FINALIZE
  -> FINALIZED
```

流程阶段不能替代详细门禁判断；`READY_TO_FINALIZE` 必须由当前版本实时计算，而不是由调用方直接设置。

版本失效规则：

- 修改需求创建新版本，并撤销大纲确认、取消旧版本未完成生成任务、清除定稿资格；
- 修改大纲创建新版本并撤销大纲确认，旧大纲上的未完成任务变为 `CANCELLED`；
- 已完成的旧章节版本保留用于审计和比较，但不能成为新大纲的当前章节；
- 修改或重生成章节只创建候选版本，不改变当前采纳版本；
- 定稿后继续修改必须创建新的方案修订，原定稿保持不可变。

## 7. 分章生成状态机

正常路径：

```text
PENDING -> RETRIEVING -> GENERATING -> VERIFYING -> SUCCEEDED
```

其他终态：

- `INSUFFICIENT_EVIDENCE`：检索成功但不满足章节最低证据规则，不调用模型；
- `FAILED_RETRYABLE`：超时、临时端口故障或可恢复资源故障；
- `FAILED_MANUAL`：非法结构、规则冲突或不可自动处理的数据；
- `CANCELLED`：需求、大纲或章节基线已变化。

每次状态转换必须先验证当前版本栅栏。任务恢复从最后成功持久化的状态继续；业务内核只定义恢复决定，不实现持久化调度器。

## 8. 端口契约

### 8.1 `SolutionModelPort`

端口接收结构化 `SolutionModelRequest`，其中仅包含：

- 场景：需求提取、大纲生成、章节生成或引用核验；
- 已确认需求的必要字段；
- 当前章节目标和模板规则；
- 本次最小 Evidence 包；
- Prompt 引用和截止时间；
- 幂等键与追踪 ID。

系统规则、用户需求和证据必须是独立字段，不能提前拼接为无法区分来源的字符串。端口返回结构化结果、模型逻辑标识、Token、费用和延迟摘要。业务内核不接触供应商错误正文。

### 8.2 `RetrievalService`

每个章节使用当前确认需求、章节目标和检索提示构造 `RetrievalQuery`。调用方不得提交主体集合或安全判断时间。返回的 Evidence Pack 是本次生成唯一可引用证据白名单。

证据不足规则由章节模板和内核策略判断。证据数不足、定位无效或全部证据被最终授权过滤时，尝试进入 `INSUFFICIENT_EVIDENCE`。

### 8.3 `CitationVerificationPort`

本地确定性校验通过后，端口可对声明与证据的语义支持性作补充判断。端口只能返回本次声明 ID，未知、重复、缺失、null 或异常结果使语义核验不可用。

语义核验不可用时，普通声明进入人工评审，高风险声明保持未解决；不得默认标记为支持。

### 8.4 `EvidenceAccessPort`

定稿前一次性接收用户、空间、待定稿 Evidence ID 集合和服务端时间，从权威源复核当前可访问性。返回未知 ID、null 或抛错时整体失败关闭；明确拒绝任一 Evidence 时阻止定稿。

### 8.5 `SolutionAuthorizationPort`

端口判断用户是否可执行 `EDIT_REQUIREMENTS`、`CONFIRM_REQUIREMENTS`、`CONFIRM_OUTLINE`、`ADOPT_SECTION`、`CONFIRM_RISK` 和 `FINALIZE`。业务内核不硬编码钉钉角色名称。授权异常按拒绝处理并写失败审计。

## 9. 引用核验与风险门禁

引用结果固定为：

- `SUPPORTED`：证据直接支持整个陈述；
- `PARTIAL`：仅支持部分陈述；
- `UNSUPPORTED`：证据不支持陈述；
- `HUMAN_CONFIRMATION_REQUIRED`：证据支持，但规则要求人工负责。

默认高风险类型：

- `AMOUNT_OR_PRICE`；
- `DATE_OR_DURATION`；
- `PERFORMANCE_OR_SLA`；
- `CUSTOMER_OR_CASE_FACT`；
- `COMPANY_OR_PRODUCT_CAPABILITY`；
- `LEGAL_OR_COMPLIANCE_COMMITMENT`。

核验顺序：

1. 检查结构、Evidence 白名单和来源定位；
2. 本地检查数字、金额、日期、名称及证据正文的一致性；
3. 可用时执行语义支持性核验；
4. 应用高风险规则；
5. 生成不可变 `SolutionRiskReport`。

`PARTIAL` 和 `UNSUPPORTED` 在未解决前阻止采纳与定稿。高风险事实即使为 `SUPPORTED`，仍可按模板要求转为 `HUMAN_CONFIRMATION_REQUIRED`。

风险确认记录必须绑定准确的声明版本、问题版本、确认人、原因和时间。声明正文或引用变化后，旧确认自动失效。

## 10. 定稿门禁

定稿前必须同时满足：

1. 当前需求和当前大纲均已确认；
2. 所有必填章节都有当前 `ADOPTED` 版本；
3. 没有未解决的 `PARTIAL` 或 `UNSUPPORTED`；
4. 所有要求人工确认的高风险声明都有当前有效确认；
5. EvidenceAccessPort 确认所有引用仍可访问；
6. 核验报告绑定的需求、大纲和章节版本与当前指针完全一致；
7. 调用用户拥有 `FINALIZE` 权限；
8. 定稿审计成功写入。

任何条件失败都不创建定稿版本。成功后生成不可变 `FinalizedSolutionVersion`，包含当前版本清单和内容摘要哈希，不包含对象存储键或下载地址。

## 11. 幂等、并发与迟到结果

- 生成幂等键至少覆盖方案、需求版本、大纲版本、章节 ID、基线章节版本和用户请求键；
- 同一幂等键的并发开始只允许一个逻辑尝试进入执行；
- 重试复用同一尝试和费用台账，不产生第二个成功版本；
- 模型或核验结果返回时重新读取版本栅栏；过期结果转为 `CANCELLED`；
- 章节保存使用期望乐观版本，冲突返回领域冲突结果，不自动重放用户文本；
- 取消是业务状态，不假设一定能中止已经发出的远程请求；迟到响应仍必须被栅栏丢弃。

## 12. 失败处理

- 检索整体不可用：`FAILED_RETRYABLE`，不调用模型；
- 证据不足：`INSUFFICIENT_EVIDENCE`，由用户补充资料或调整章节目标；
- 模型超时或暂时不可用：`FAILED_RETRYABLE`；
- 模型结构非法或引用集合非法：`FAILED_MANUAL`；
- 语义核验不可用：保留候选草稿并进入人工评审，高风险项不自动通过；
- Evidence 当前访问复核失败：阻止定稿，不泄漏被撤权来源；
- 审计失败：成功业务结果不得对外返回；记录失败审计失败时保留原业务异常并附加审计异常；
- 任一失败都不得删除已确认需求、大纲、已采纳章节或人工编辑。

领域异常使用固定错误码和无正文消息，不包含需求正文、章节正文、Evidence 摘要、模型输出或供应商错误正文。

## 13. 安全与审计

文档证据和客户需求均作为不可信数据，不能覆盖系统规则。模型响应也作为不可信输入处理。

审计允许记录：

- request/solution/requirement/outline/section/attempt ID；
- actor、space、动作和结果；
- Prompt 与模型逻辑版本；
- 检索、Evidence、Claim、风险数量；
- 状态转换、规范化错误码、耗时、Token 和费用摘要；
- 人工确认类型、确认人和原因代码。

审计不得记录完整需求、章节正文、Evidence 摘要、主体集合、供应商错误正文、异常堆栈、密钥或外部模型请求体。

本批不实现真实出网，但端口契约保证将来只有模型网关适配器可以访问云模型。

## 14. 测试与纵向验收

所有业务能力使用 TDD。测试分为：

### 14.1 领域测试

- 不可变值对象、集合防御性复制和版本关系；
- 需求/大纲确认与修改后的失效；
- 必填章节、重复 ID、层级和状态转换不变量；
- 乐观版本冲突和定稿不可变性。

### 14.2 生成编排测试

- 未确认需求或大纲时检索和模型调用次数均为 0；
- 证据不足时不调用模型；
- 检索、模型、核验的异常分类；
- 未知、重复、缺失 Evidence ID 时整体拒绝；
- 旧任务迟到、取消和幂等重试；
- 同一幂等键只有一个章节版本和一条费用摘要。

### 14.3 引用与风险测试

- 真实但不相关引用为 `UNSUPPORTED`；
- 部分支持为 `PARTIAL`；
- 数字、金额、日期和名称差异不会被忽略；
- 高风险声明需要有效人工确认；
- 声明或引用变化后确认失效；
- Evidence 撤权、未知返回和授权异常阻止定稿。

### 14.4 内存纵向验收

`SolutionWorkbenchCoreAcceptanceTest` 使用固定时钟、确定性 ID、内存方案仓储、现有可信检索服务、假模型和内存核验端口，依次验证：

1. 创建方案并修订、确认需求；
2. 生成、调整并确认大纲；
3. 一个章节因证据不足停止且不调用模型；
4. 一个章节生成带合法 Evidence ID 的候选稿；
5. 不支持引用阻止采纳；
6. 修订后生成支持性引用；
7. 金额或工期声明在人工确认前阻止定稿；
8. 确认风险、采纳所有必填章节并通过 Evidence 当前权限复核；
9. 创建不可变定稿版本；
10. 修改需求后旧大纲、生成任务、风险确认和定稿资格全部失效；
11. 固定输入得到确定性版本关系、状态和审计计数。

验收夹具只放在测试源码，不新增生产内存仓储、假模型后门或绕过授权的 Profile。

## 15. 完成标准与后续门槛

本批完成标准：

- 上述领域、编排、引用、风险和纵向验收测试全部通过；
- 现有 Java、前端、Python 和 Playwright 回归保持绿色；
- 业务模块无新增产品依赖；
- 中文运行手册明确默认策略、状态、失败语义和后续适配要求；
- 独立审查确认旧任务、幂等、引用白名单、撤权和定稿门禁无高风险缺陷；
- `pilot-retrieval-v1` 与 `pilot-workbench-v1` 均不存在。

后续只有在 PostgreSQL、OpenSearch、真实授权适配器和检索质量门槛完成后，才能进入完整工作台实施计划。届时按顺序增加：

1. PostgreSQL/Flyway 与可恢复任务适配器；
2. 经审批的模型网关和 Prompt 内容；
