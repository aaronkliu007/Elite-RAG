# 可信检索内核设计

**日期：** 2026-09-28
**状态：** 待书面评审
**适用阶段：** 可信检索阶段的基础设施中立切片

## 1. 背景与意图

知识底座已经具备主体与 ACL、文档版本、安全上传、统一解析、入库编排、人工发布和审计等业务能力。真实 PostgreSQL、OpenSearch、Embedding 与 Reranker 基础设施尚未确定，因此当前不能宣称完成生产检索，也不能创建 `pilot-retrieval-v1` 标签。

本切片的目的不是模拟一套临时搜索系统，而是先交付可以长期保留的纯 Java 检索内核：固定领域契约、权限边界、融合算法、降级语义、证据筛选和来源定位。未来接入真实基础设施时，只新增端口适配器，不改业务规则。

主要使用者是后续的检索 API、方案生成工作台和离线评估程序。成功标准是使用纯内存适配器即可重复验证“查询—召回—融合—重排—二次授权—证据包”完整链路，并证明检索期间发生权限或发布状态变化时不会泄漏候选。

## 2. 范围

### 2.1 本批包含

- 检索查询、候选、证据包和来源定位的纯领域契约。
- 全文与向量双路召回端口。
- 有界并行召回、单路降级和双路失败语义。
- Reciprocal Rank Fusion（RRF）融合及稳定排序。
- 可选重排、重排失败降级。
- 中文近重复过滤、单文档占比限制和最终数量限制。
- 返回前批量复核 ACL、空间归属、当前发布版本和有效期。
- 纯内存端口的端到端验收与单元测试。

### 2.2 本批不包含

- PostgreSQL Schema、Flyway、事务 Outbox 和真实授权查询适配器。
- OpenSearch Mapping、索引投影、重建、别名切换和 Testcontainers。
- Spring AI、云端 Embedding、云端 Reranker 或供应商 SDK。
- HTTP 检索/引用 API、预览 URL、Vue 来源查看器。
- 黄金评估集、质量基线或发布标签。
- 方案生成、问答、Agent、知识图谱或自动执行工具。

以上能力仍按 `docs/superpowers/plans/2026-09-24-trusted-retrieval.md` 后续任务交付。本切片通过不代表可信检索阶段整体通过。

## 3. 架构与边界

代码放在 `com.yunjihai.rag.retrieval` 下，并按职责分为三个小边界：

1. `domain`：值对象、来源定位、结果状态和不变量，不依赖 Spring、OpenSearch 或模型 SDK。
2. `search`：全文/向量召回端口、RRF 融合与有界并行调度。
3. `selection`：重排端口、批量授权端口、近重复与多样性选择。

`PrincipalResolverPort` 负责在服务端展开调用用户当前有效主体。调用方不能提交或覆盖主体集合。`Clock` 由装配层注入，用于捕获召回开始时间和返回前授权复核时间，调用方不能指定安全判断时间。

对外保留单一业务入口：

```java
public interface RetrievalService {
    EvidencePack retrieve(RetrievalQuery query);
}
```

`TrustedRetrievalService` 组合召回与筛选服务。调用方不接触任何具体搜索引擎或模型类型。

## 4. 领域契约

### 4.1 RetrievalQuery

查询至少包含：

- `requestId`：调用方提供的不透明关联 ID，用于审计和排障。
- `userId`、`spaceId`：权限与空间边界。
- `queryText`：非空，规范化后有长度上限；不写入普通日志。
- `metadataFilter`：行业、产品、方案类型、年份等可选条件。
- `requestedEvidenceCount`：只能为 8–15。

`RetrievalQuery` 不接收主体集合、发布状态或安全判断时间。服务端使用 `PrincipalResolverPort` 与注入的 `Clock` 创建内部 `RetrievalContext`；有效主体必须包含当前用户主体。调用方不能通过元数据条件放宽空间、发布、权限或有效期约束。

### 4.2 RetrievalFilter

传给每个召回端口的统一过滤器固定包含：

- 知识空间 ID；
- 有效主体集合；
- `currentPublishedOnly=true`；
- 查询时间；
- 业务元数据条件。

全文和向量端口必须接收同一个不可变过滤器。端口实现不得提供跳过安全过滤的重载。

### 4.3 Candidate

候选必须包含稳定候选 ID、文档 ID、版本 ID、结构节点 ID、文本、标题路径、来源定位、召回来源、原始排名和可选原始分数。候选不包含对象存储地址、签名 URL 或供应商响应对象。

候选构造时即校验：

- 文档、版本、节点和候选 ID 非空；
- 文本非空且长度有界；
- 来源定位完整；
- 排名从 1 开始；
- 召回来源只能是 `LEXICAL` 或 `VECTOR`。

### 4.4 SourceLocator

`SourceLocator` 是密封接口，首批支持：

- `PageLocator`：页码必填，边界框可选；有边界框时坐标必须归一化且有效。
- `SlideLocator`：幻灯片页码必填。
- `TableLocator`：工作表/表格名称与区域范围必填；范围使用服务端解析后的结构化起止行列，不接收客户端拼接公式。
- `MarkdownLocator`：标题路径或结构节点 ID 至少有一个。

来源信息不足时拒绝创建定位对象，禁止把未知位置伪装成精确页码或表格范围。

### 4.5 Evidence 与 EvidencePack

`Evidence` 只暴露不透明证据 ID、文档/版本/节点 ID、标题、有限长度摘要、最终分数和来源定位。证据 ID 由可注入的 `EvidenceIdFactory` 生成，测试使用确定性实现，生产可使用 UUIDv7。

`EvidencePack` 包含请求 ID、证据列表和执行状态：

- `degraded`：是否发生召回或重排降级；
- `degradationReasons`：结构化原因集合，不包含异常堆栈或敏感正文；
- `recallCounts`、`reauthorizedCount`、`selectedCount`：用于指标和审计；
- `completedAt`。

证据列表最多 15 条，可以为空。合法证据不足时按实际数量返回，不使用低质量或未授权候选补足。

## 5. 检索数据流

1. `TrustedRetrievalService` 校验并规范化查询，记录服务端开始时间。
2. 通过 `PrincipalResolverPort` 展开当前有效主体，构造唯一 `RetrievalFilter`，同时交给全文和向量端口。
3. `HybridRecallService` 在注入的有界执行器中并行执行两路召回，每路最多接收 50 条。
4. 对两路健康结果执行 RRF，按候选 ID 合并同一候选，并保留各分支排名信息。
5. 取融合后的前 30 条交给 `RerankerPort`；重排健康时使用重排分数，否则保留 RRF 顺序。
6. 再次读取服务端当前时间，`RetrievalAuthorizationPort` 使用用户 ID 对候选涉及的文档/版本执行一次批量权威复核；端口在权威源内解析用户此刻的主体关系，不复用召回阶段的主体快照。
7. 只保留仍属于目标空间、仍是当前发布版本、ACL 有效且未过期的候选。
8. `EvidenceSelectionService` 执行近重复过滤、单文档上限和最终数量限制。
9. 生成证据 ID 并返回 `EvidencePack`。

权限复核发生在重排之后、证据选择之前，从而限制权威存储查询量，同时保证召回后 ACL 变化不会泄漏到最终结果。

## 6. 排名与多样性规则

### 6.1 RRF

默认 `k=60`，可由配置对象注入。候选分数为其在所有健康分支上的：

```text
sum(1 / (k + rank))
```

融合排序依次比较 RRF 分数降序、最佳分支排名升序、候选 ID 升序。禁止依赖 Map 遍历顺序，保证相同输入产生相同输出。

### 6.2 重排

重排最多接收 30 条候选，只允许调整顺序和分数，不允许新增候选、修改来源定位或跨空间替换文档。返回未知、重复或缺失候选 ID 时，整个重排结果视为非法并降级到 RRF 顺序。

### 6.3 近重复与单文档上限

近重复比较使用规范化文本的中文字符 3-gram Jaccard 相似度：

- Unicode 规范化；
- 转小写；
- 合并空白并去除仅用于排版的标点；
- 默认阈值 0.85，可配置；
- 短于 3 个字符时按规范化全文精确比较。

按当前排名从高到低选择，和已选证据近重复的候选跳过。每个文档默认最多 3 条，最终取查询要求的 8–15 条。阈值和上限集中在 `RetrievalPolicy`，不散落在服务代码中。

## 7. 权限与安全语义

召回阶段的主体过滤是性能与第一道隔离，不能作为最终授权事实。召回主体由服务端解析，不能来自客户端。`RetrievalAuthorizationPort` 必须从权威源重新解析用户当前主体，并批量返回每个文档版本的判定；接口结果需能区分允许与拒绝，但对外统一隐藏拒绝原因。

复核至少验证：

- 文档存在且属于查询空间；
- 文档未归档；
- 候选版本仍是当前发布版本且状态为 `PUBLISHED`；
- 用户当前有效主体仍拥有读取权限；
- 文档与授权有效期在返回前的授权复核时刻有效。

权威复核异常时整体失败关闭，不返回部分候选。明确拒绝的候选被静默剔除，避免通过结果差异泄露资源存在性。

查询正文、候选正文和证据正文不得写入普通日志或审计元数据。允许记录查询摘要哈希、请求 ID、空间 ID、候选数量、耗时、降级原因和最终数量。

## 8. 失败与降级

- 全文或向量单分支异常、超时或返回非法结果：使用健康分支并标记降级。
- 两个召回分支都失败：抛出 `RetrievalUnavailableException`，不返回空结果伪装成功。
- 两个分支都健康但没有命中：返回成功的空证据包。
- 重排异常、超时或结果非法：退回 RRF 顺序并标记降级。
- 主体解析或授权复核异常：抛出 `RetrievalAuthorizationUnavailableException`，整体失败关闭。
- 授权复核全部拒绝：返回成功的空证据包。
- 单个候选领域数据非法：端口边界拒绝该分支结果；不得在最终阶段猜测或补造字段。

召回与重排的超时、候选上限和策略参数通过不可变 `RetrievalPolicy` 注入。执行器由应用装配层管理生命周期，领域服务不创建全局线程池。

## 9. 测试与验收

### 9.1 契约测试

- 查询文本、主体集合、证据数量和时间不变量。
- 页码、边界框、幻灯片、表格范围和 Markdown 定位合法性。
- Evidence 不暴露对象地址或供应商字段。

### 9.2 召回测试

- 两路健康时正确计算 RRF。
- 相同分数具有稳定顺序。
- 同一候选跨分支正确合并。
- 全文失败、向量失败和单路超时均返回健康分支并标记降级。
- 两路失败抛出检索不可用。
- 每个端口收到完全相同且包含 ACL/发布/有效期约束的过滤器。

### 9.3 筛选与授权测试

- 重排最多接收 30 条。
- 重排失败或返回非法集合时退回 RRF。
- 中文近重复被过滤，非重复中文内容保留。
- 单文档最多 3 条，最终证据不超过请求上限。
- 召回后撤销 ACL、替换发布版本、归档或过期的候选被剔除。
- 调用方无法提交主体集合或安全判断时间；召回后组织成员关系变化由最终复核发现。
- 授权端口只调用一次批量接口；异常时不返回任何证据。

### 9.4 内存纵向验收

使用内存全文召回、向量召回、重排和授权端口，跑通完整业务入口，并断言：

- 有权且当前发布的候选形成可定位证据；
- 被撤权候选即使排名第一也不会出现；
- 一路故障仍有可用结果且带降级状态；
- 双路故障明确失败；
- 输出顺序和指标可重复。

本批不以搜索相关性指标作为发布门槛，因为尚无批准的脱敏黄金集；只验证算法确定性、权限安全和契约完整性。

## 10. 后续接入点与阶段门槛

基础设施准备后按以下顺序接入：

1. PostgreSQL/Flyway、发布事务 Outbox 和批量授权适配器；
2. OpenSearch 投影、全文召回、向量召回和可重建索引；
3. 经审批的 Embedding/Reranker 模型网关适配器；
4. 引用 API、来源查看器和短时授权预览；
5. 脱敏黄金集、离线指标和 `pilot-retrieval-v1` 门槛。

只有真实 PostgreSQL 事务与授权、OpenSearch 重建、权限负样本、引用定位和批准质量基线全部通过后，才能创建 `pilot-retrieval-v1`。本切片提交信息、README 和验收报告必须继续明确这一限制。
