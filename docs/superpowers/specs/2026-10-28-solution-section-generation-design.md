# 方案工作台分章生成与核验设计

## 目标

沿已交付的需求、大纲确认闭环，接入现有 `SectionGenerationService`，让员工在有权空间内请求章节草稿、查看证据核验结果并人工采纳。生成尝试、章节版本和检查点由 PostgreSQL 持久化；重试及并发请求不会重复提交章节版本。

## 交付顺序

1. 生成尝试持久化：客户端键唯一，状态按修订号比较并替换，重启后可读取；只保存 ID、状态和用量，不存模型提示词或正文。
2. 章节版本与原子提交：草稿、声明和核验结果不可变；在事务中复核需求、大纲、确认、章节基线与尝试修订号，再同时写入版本及成功状态。
3. 经审批模型适配与核验：使用已有模型网关的配置和额度边界；结构化输出必须仅引用检索证据白名单；语义核验不可用时要求人工确认。
4. HTTP 与页面：会话鉴权、来源权限重验、版本冲突、幂等重放、结果及风险展示、人工采纳；调用前后均重验权限和版本。

## 安全与恢复

一家企业独立部署一套实例。生成输入只含当前有权需求、章节与检索证据。任何无权或来源失效请求在调用外部模型前失败关闭。模型、检索异常记录脱敏错误码，不在日志及幂等表保存正文。任务恢复须通过持久化状态和有界租约判断；中断于模型或核验阶段的任务不得永久停留，重复调用不得产生两份草稿。引用不属于证据白名单、量化值冲突或语义核验失败均不得自动采纳。人工采纳仍要求当前需求、大纲、章节基线有效。

## 验收

真实 PostgreSQL 测试覆盖迁移、重启读取、并发注册、CAS 冲突、检查点与原子回滚。服务/API 测试覆盖权限、来源撤销、版本陈旧、证据不足、模型失败、引用越界和人工采纳。页面测试覆盖生成状态、核验结果、冲突与窄屏。最终运行仓库统一验证；生产准入、Word 导出和钉钉同步仍按原计划另行交付。
