# Grounded QA 语义冲突检测补充设计

## 1. 意图

补齐现有问答编排对跨文档关键事实冲突的识别能力。当已授权证据对同一事实给出不同金额、期限、日期、比例、容量、数量或启停状态时，在任何脱敏和模型调用前稳定返回 `CONFLICTING_EVIDENCE`，避免模型自行选择或调和互相矛盾的资料。

## 2. 目标与非目标

目标：

- 保留现有“同一证据身份对应不同正文”的完整性冲突检查；
- 识别具有明确键值表达的高置信事实冲突；
- 等价单位和值不误判，例如 `1 万元` 与 `10000 元`、`1 年` 与 `12 个月`；
- 检测器异常时严格拒答，不调用模型；
- 通过独立端口保持规则包、客户定制实现或未来审批模型检测器的替换能力。

非目标：

- 不尝试首版解决所有自然语言矛盾、反讽、条件例外或时态推理；
- 不调用额外云模型，不增加模型费用和外发内容；
- 不自动判断哪份冲突资料更权威，也不输出推测性答案；
- 不修改现有拒答码、数据库状态机或 Web 响应契约。

## 3. 方案比较

### 方案 A：直接使用聊天模型判断

覆盖面较广，但会增加外发、费用、延迟和模型不确定性；检测器故障还会扩大问答链路的失败面，不适合作为首版安全底线。

### 方案 B：在 `GroundedQaService` 中继续堆叠正则

改动最少，但编排服务会同时承担事实抽取和冲突规则，后续客户定制困难，也不利于独立验证误判边界。

### 方案 C：独立端口加确定性高精度实现

新增 `EvidenceConflictDetector` 端口，由内置确定性实现完成 Unicode 归一化、显式键值事实抽取、单位换算和跨证据比较。问答编排只消费布尔结论并保持失败关闭。首版采用此方案，因为它不新增外发且能在安全性、可解释性和扩展性之间取得平衡。

## 4. 领域与算法边界

`EvidenceConflictDetector.hasConflict(List<Evidence>)` 只接收已经完成最终鉴权和证据限量的检索结果。

确定性实现按以下顺序处理：

1. 对标题和正文执行 NFKC、空白与标点归一化；
2. 检查相同 `spaceId/documentId/versionId/nodeId` 是否出现不一致内容；
3. 从正文中提取显式的“事实键 + 分隔词 + 类型化值”，分隔词包括冒号、`为`、`是`、`设为`、`设置为` 和 `定为`；
4. 类型化值只覆盖高置信类别：日期、金额、天数、月/年期限、比例、容量、QPS/TPS、人数/台数和启停/有效/允许状态；
5. 对金额、月年期限、容量和同义状态做规范化；
6. 仅比较不同证据项；事实键完全相同，或一方是另一方不少于四个码点的语义后缀时，规范值不同即判定冲突；
7. 无法类型化的自由文本不参与首版冲突判定，避免过度拒答。

检测器不得记录问题、证据正文或抽取出的业务值。任何运行时异常由编排层按严格拒答处理。

## 5. 编排与结果

冲突检测位于“证据数量/分数检查”之后、“构建证据包、脱敏和调用聊天模型”之前：

- `false`：继续现有链路；
- `true`：完成请求并返回 `RefusalReason.CONFLICTING_EVIDENCE`；
- 检测器抛出异常：同样严格拒答为 `CONFLICTING_EVIDENCE`，且不调用脱敏器或模型。

评测服务继续复用同一 `GroundedQaService`，不建立旁路。

## 6. 扩展与验收

生产默认 Bean 通过 Spring Boot 自动配置提供，并在部署方声明自定义 `EvidenceConflictDetector` 时自动退让。不同公司可在独立部署实例中替换该端口，实现行业词典、结构化元数据或经过审批的模型检测，但必须保持：只接收已授权证据、异常失败关闭、模型调用前执行、不得输出原文日志。

验收至少覆盖：

- 不同文档对同一金额、期限、日期和状态给出不同值时严格拒答；
- 等价单位和值不冲突；
- 相似但不同的事实键不冲突；
- 同一证据内部出现多个数字不被当作跨证据冲突；
- 检测器异常时严格拒答且模型调用次数为零；
- 原有同身份不同正文冲突继续生效。
