# 企业知识库核心管理闭环设计

**日期：** 2026-10-08

**适用阶段：** 方案 A 第一条纵向闭环

**状态：** 已完成会话评审，待书面规格确认

## 1. 背景与目标

仓库已经具备知识底座、PostgreSQL 与 AIStor/MinIO 持久化、文档解析、可信检索内核、OpenSearch 检索投影和方案工作台领域内核，但当前仍缺少员工可直接使用的完整身份、权限、业务 API 和管理界面。

本批目标是在现有基础上交付一条可独立运行、可演示、可受控测试的知识库管理闭环：

> 本地登录 → 用户与角色管理 → 知识空间授权 → 文档上传与解析 → 人工审核与发布 → 权限过滤的全文检索 → 来源查看与下载。

公司现阶段约 100 人，首版按“一家公司独立部署一套实例”设计。系统必须保留面向不同公司交付时的扩展性，但不提前建设 SaaS 多租户、动态插件市场或用户自定义角色系统。

## 2. 已确认约束

- 在项目根目录工作。
- 文档、界面、运行手册和交付说明使用中文。
- 数据留在内网，仅允许调用经过审批的云端模型 API。
- 首版使用本地账号；钉钉登录和组织同步属于后续外围集成。
- Web 登录使用服务端 Session，不向浏览器签发长期 JWT。
- 首版采用固定角色，不提供自定义角色编辑器。
- 每家公司独立部署一套实例，不实现同实例 SaaS 多租户。
- Spring Boot 是业务、权限、事务和审计的唯一所有者。
- Python Worker 只负责无状态解析，不持有数据库、对象存储、身份源或模型密钥。
- PostgreSQL 是业务和权限权威源；OpenSearch 只是可重建的检索投影。
- 当前批次不调用真实 Embedding、Reranker 或聊天模型；生产配置未提供真实 Embedding 时只启用全文检索。

## 3. 范围

### 3.1 本批包含

- 本地账号登录、退出、当前会话查询和服务端 Session；
- 用户创建、启停、密码重置和系统管理员授权；
- 五类固定角色及空间级角色分配；
- 知识空间创建、查询、成员与角色管理；
- Word、Excel、PDF、PPT、Markdown、PNG 上传；
- 文档版本、解析状态、预览、下载和失败重试；
- 提交审核、驳回、发布、归档和历史版本追溯；
- OpenSearch 全文检索、分页、过滤、来源定位和 PostgreSQL 最终鉴权；
- 登录、授权、文档生命周期、下载和检索的脱敏审计；
- 对应 Vue 管理界面、自动化测试和运行说明。

### 3.2 本批不包含

- 钉钉登录、组织同步或事件回调；
- 真实 Embedding、Reranker、聊天模型或模型供应商密钥；
- 带生成答案的 RAG 问答；
- 报表生成、方案设计、Word 导出和可配置工作流；
- SaaS 多租户、动态插件市场或用户自定义角色；
- 企业杀毒产品集成、正式备份恢复演练、渗透测试和容量压测；
- 真实敏感资料试点和正式生产准入声明。

真实模型网关、带引用问答和检索质量评测属于方案 A 第二条纵向闭环。

## 4. 总体架构

系统保持模块化单体和现有技术边界：

```text
Vue Web
   │ HTTPS + Secure/HttpOnly Session Cookie + CSRF
   ▼
Spring Boot Core API
   ├── Identity：内部用户、外部身份、本地凭据、会话
   ├── Access：固定角色、空间授权、动作决策
   ├── Knowledge：空间、文档、版本、审核、发布、归档
   ├── Ingestion：上传、对象存储、解析任务编排
   ├── Retrieval：全文召回、证据筛选、最终鉴权
   └── Audit：脱敏业务审计
   │                │                 │
   ▼                ▼                 ▼
PostgreSQL       AIStor/MinIO      OpenSearch
权威数据与权限     不可变原始对象      可重建检索投影
   │
   └── Parser Contract ──► Python Parser Worker
                           无状态文档解析
```

领域模块通过稳定端口依赖身份源、对象存储、解析器和检索引擎。具体适配器不得反向渗透到领域对象。不同公司通过部署配置、适配器选择和策略参数完成定制。

首版不增加租户表或逐行业务 `tenant_id`。因为每家公司使用独立数据库、对象桶和索引，这些部署边界本身就是数据隔离边界。若未来明确转为共享实例 SaaS，再以独立架构批次引入租户隔离，禁止仅靠临时查询条件伪造多租户安全。

## 5. 身份与会话

### 5.1 身份模型

身份分为三层：

- `User`：内部稳定用户，主键为 UUID，保存显示名、状态和会话版本；
- `ExternalIdentity`：身份提供方与外部主体的绑定，例如 `LOCAL/zhangsan`，未来可增加 `DINGTALK/<userId>`；
- `Credential`：本地身份适配器专用凭据，保存密码哈希、失败次数和临时锁定状态。

业务对象只引用内部用户 ID，不引用用户名、手机号或钉钉用户 ID。未来绑定钉钉身份时不改变文档、ACL 或审计外键。

### 5.2 本地账号

- 不开放自助注册；
- 系统管理员创建普通用户；
- 密码长度为 12 至 128 个字符，使用 BCrypt 保存，默认 cost 为 12；不保存或记录明文；
- 登录错误不区分账号不存在和密码错误；
- 同一账号 15 分钟内连续失败 5 次后锁定 15 分钟；同时按来源 IP 限速，账号不存在时也执行等价耗时的密码校验；
- 管理员重置密码后递增用户会话版本，使所有旧会话失效。

初始系统管理员通过部署密钥一次性引导。引导逻辑仅在数据库中不存在系统管理员时执行；系统已有管理员后忽略引导凭据。禁止采用“第一个注册用户自动成为管理员”的规则。

### 5.3 Session

- Session 保存在服务端，浏览器只持有不透明 Cookie；
- Cookie 使用 `HttpOnly`、`Secure`、`SameSite=Lax`；
- 修改类请求必须携带 CSRF Token；
- 默认闲置超时 30 分钟，绝对有效期 8 小时；
- 首版不提供“记住我”；
- 每次认证请求校验用户状态和 `sessionVersion`；
- 用户停用、密码重置或系统管理员角色变更时递增 `sessionVersion`；空间角色和成员变更不依赖 Session 缓存，下一次授权查询立即生效；
- 退出登录销毁当前 Session。

## 6. 固定角色与授权

### 6.1 角色

| 角色 | 作用域 | 核心能力 |
|---|---|---|
| 系统管理员 | 全局 | 管理用户、创建知识空间、查看系统审计 |
| 空间管理员 | 空间 | 管理空间资料、成员、空间角色和 ACL |
| 编辑者 | 空间 | 上传文档、创建版本、编辑元数据、提交审核 |
| 审核发布者 | 空间 | 审核、驳回和发布文档 |
| 只读成员 | 空间 | 浏览、下载和检索已发布内容 |

同一用户可以在不同空间拥有不同角色，也可以在同一空间叠加角色。授权结果取允许动作的并集，但所有资源状态约束仍必须满足。

### 6.2 授权原则

- 默认拒绝；
- Controller 不直接判断角色，只向授权服务询问“用户能否对资源执行动作”；
- OpenSearch 中的字段不能作为最终授权依据；
- 文档详情、下载、预览和检索证据返回前均重新查询 PostgreSQL；
- 无权访问与资源不存在对普通用户表现为相同语义；
- 后端在 DTO 中返回当前用户可执行动作集合，供前端控制界面，但前端状态不构成安全边界；
- 角色授予、撤销和成员移除必须写入脱敏审计。

## 7. 文档业务流程

### 7.1 上传与解析

1. 编辑者选择知识空间，提交文件和标题、分类、标签等元数据；
2. Java 服务校验权限、扩展名、MIME、文件签名、大小、压缩炸弹和加密文档；
3. 原文件以不可变对象写入 AIStor/MinIO；
4. PostgreSQL 创建文档、不可变版本和解析任务；
5. Python Worker 按版本化契约解析文件并返回 Canonical Document；
6. Java 校验解析结果并持久化 Canonical Document；
7. 成功版本保持 `DRAFT`，允许提交审核；失败版本保留稳定错误码并允许重新处理，不产生可检索内容。

上传接口异步返回文档和版本标识。前端轮询解析状态；首版不引入 WebSocket。

### 7.2 审核与发布

- 只有解析成功且必填元数据完整的 `DRAFT` 版本可以提交审核；
- 提交后状态变为 `IN_REVIEW`；
- 审核发布者可以发布，也可以填写审核意见后驳回；
- 驳回使该版本回到 `DRAFT`，审核意见不可被编辑者覆盖；
- 发布在同一数据库事务中更新当前发布版本、写审计并创建检索投影事件；
- 每个文档最多只有一个当前发布版本；发布新版本原子切换当前指针；
- 旧版本保持不可变并可供授权用户审计追溯；
- 归档后文档不可继续检索，恢复能力不属于本批范围。

### 7.3 检索

1. 用户提交查询、空间范围、文档类型或时间等过滤条件；
2. OpenSearch 执行全文召回；
3. 可信检索内核完成结果整理和证据选择；
4. 返回前使用一次 PostgreSQL 批量查询复核候选访问权；
5. 只返回当前已发布且仍被授权的版本与来源片段；
6. 用户可从结果进入文档详情、来源定位和授权下载。

现有混合检索结构保持不变，但本批生产配置没有真实 Embedding 时关闭向量分支。自动化测试允许使用确定性向量实现验证编排，禁止把测试向量注册为生产能力。

## 8. HTTP API 与前端

### 8.1 API 分组

- `/api/v1/session`：登录、退出、当前会话和 CSRF；
- `/api/v1/admin/users`：用户创建、启停、密码重置和全局角色；
- `/api/v1/knowledge-spaces`：空间、成员和空间角色；
- `/api/v1/documents`：上传、版本、解析状态、预览、下载、审核、发布和归档；
- `/api/v1/search`：查询、过滤、分页、证据和来源定位。

所有请求与响应使用独立 DTO，不暴露数据库行、凭据字段或领域聚合内部结构。API 使用统一错误信封，至少包含稳定错误码、中文消息、追踪 ID 和可选字段错误；不得向客户端返回堆栈、SQL、内部主机名或供应商错误正文。

上传、提交审核、驳回、发布和成员授权等关键写操作接受幂等键。幂等范围由“认证用户、操作类型、幂等键”共同确定，服务端保存输入哈希和结果至少 24 小时。同一范围内相同输入复用原结果；同一键对应不同输入返回冲突。

### 8.2 前端页面

- 登录页；
- 知识空间首页和空间详情页；
- 用户管理页；
- 空间成员与角色管理页；
- 文档上传页；
- 文档详情、版本、解析状态与审核页；
- 全文检索和来源查看页。

路由守卫只用于用户体验；未登录和越权必须由后端拦截。界面根据后端返回的可执行动作集合显示或隐藏按钮，并为加载、空数据、失败、权限不足、解析中和索引延迟提供明确状态。

## 9. 一致性、失败与恢复

### 9.1 权威源与事务

- PostgreSQL 是用户、角色、ACL、文档生命周期和发布状态的唯一权威源；
- 业务状态、审计和 Outbox 事件在可行时同事务提交；
- OpenSearch 和 AIStor/MinIO 不得反向覆盖 PostgreSQL；
- 对象写入成功而数据库事务失败时登记清理候选；
- 发布成功而 OpenSearch 尚未更新时，界面显示索引等待状态，权威发布状态不回滚。

### 9.2 异步任务

- 解析与投影任务使用租约、超时回收、有限重试和死信状态；
- 重试必须幂等；
- 管理员可查看失败错误码并重新入队；
- 任务正文、原文片段和凭据不得写入错误日志；
- 授权数据库不可用时检索整体失败关闭；
- OpenSearch 全部不可用时返回明确“检索服务不可用”，不伪造空结果。

### 9.3 并发

- 文档聚合、版本发布指针和空间成员变更使用乐观锁或等价条件更新；
- 并发冲突返回稳定冲突错误，前端刷新数据后允许用户重新提交；
- 同一文档并发发布不得产生两个当前发布版本；
- 同一成员和角色的重复授权必须收敛为单一事实。

## 10. 安全与隐私

- 日志和审计禁止记录密码、Session、CSRF Token、原始文件正文、解析正文、ACL 明细和密钥；
- 数据库、AIStor、OpenSearch 和未来模型密钥只通过部署密钥注入；
- 仓库、镜像、前端资源、日志和工单不得包含密钥；
- 每次下载重新鉴权；临时 URL 必须短时有效并绑定单一对象；
- 上传安全扫描通过独立端口实现；未接入企业级恶意文件扫描器的环境不得宣称生产可用；
- 业务审计与技术日志分开保存；
- 健康检查不得回显凭据、连接串或内部错误正文；
- 记录登录失败、解析积压、索引积压、任务重试、鉴权拒绝和依赖健康度指标。

## 11. 测试策略

### 11.1 自动化分层

- 领域单元测试：角色动作矩阵、文档状态、版本切换、幂等和默认拒绝；
- 安全测试：登录限速、Session 失效、CSRF、越权、资源枚举、停用用户和权限撤销；
- 基础设施集成测试：真实 PostgreSQL、AIStor/MinIO、OpenSearch 容器中的事务、补偿、Outbox、租约和最终鉴权；
- 解析契约测试：六类文件的成功、损坏、加密、超限和超时场景；
- API 测试：DTO、错误码、分页、幂等键和授权结果；
- 前端测试：Vitest 覆盖状态与权限呈现，Playwright 覆盖关键用户流程；
- 完整验收测试：登录、上传、解析、审核、发布、投影、检索、来源查看和下载全链路。

### 11.2 业务验收标准

1. 引导管理员能够登录、创建用户和知识空间；
2. 管理员能够给不同用户分配空间级角色；
3. 六类文件都能上传并进入可观察的异步解析流程；
4. 编辑者可以提交审核但不能发布；
5. 审核发布者可以驳回或发布但不能管理系统用户；
6. 只读成员只能读取、下载和检索已发布内容；
7. 发布新版本后，检索只指向当前发布版本，历史版本仍可审计追溯；
8. 撤销空间成员后，该用户下一次请求立即失去访问权，旧索引内容不能绕过最终鉴权；
9. 解析、对象存储、索引失败和重复请求可恢复，且不产生重复版本或未授权内容；
10. 未配置真实 Embedding 时明确以全文模式运行，不使用伪向量冒充生产能力；
11. 后端、前端、Python、数据库迁移、Compose 配置和端到端测试全部通过；
12. 中文界面在常见桌面宽度下无关键操作遮挡、表格溢出或嵌套滚动问题。

## 12. 完成定义

满足以下条件才可声明本批完成：

- 本文列出的所有本批范围已经实现；
- 所有验收标准均有自动化测试或可重复的验收步骤；
- 生产装配不再使用固定身份、内存仓储或 `denyAll` 占位实现；
- 所有敏感配置都通过仓库外部署密钥注入；
- 运行手册说明启动、引导管理员、故障恢复、全文降级和已知限制；
- 全部验证命令在干净环境中通过；
- 未接入真实敏感资料，未创建正式生产或试点标签；
- 文档明确列出进入正式试点前仍需完成的杀毒、备份恢复、容量和安全加固事项。
