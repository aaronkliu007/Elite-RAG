# 指定记录问答实施计划

目标是减少用户明确询问某份记录原文时，由其他记录不同内容造成的误拒；此工作不将一般语义冲突归因视为已经解决。默认严格拒答保持不变。

1. 用合成资料和反例验证记录定位：完整名称或唯一可证明的别名、当前版本、全量候选和所有节点；同名、未知来源、缺失节点、伪造摘录、复合问题及最终预算问题应保持未知。
2. 建立只适用于明确记录问题的策略，核对数据库完整上下文；答案必须完整引用目标文档所有必要节点，不推断最终事实。策略默认关闭，不能与其他策略同时启用而绕过严格策略。
3. 在 PostgreSQL、OpenSearch、对象存储的隔离环境运行 Q09—Q12 及反例，复核保存、撤权、文档变更、历史读取和审核撤销；用真实模型验证时仅发送校验过的合成资料。
4. 重跑相关回归及合成数据集，记录实际改善范围与不能保证的场景；只有核验和安全审查通过才启用该策略，不以个别正例推断通用误拒已解决。

评审重点：文档名称歧义；文档内隐藏限定与跨文档对目标记录的修正；遗漏或伪造节点；多份冲突同时存在；模型输出遗漏上下文；文档变更与撤权并发。

## 2026-11-19 安全评审结果

原型曾在合成环境中对四条记录问题返回完整摘录，但评审发现：其他文档可能直接反驳目标记录；表格正文可能遗漏单元格；名称简化可能合并不同身份；并发新增同名记录会绕过一次性目录检查；全局目录版本还会受无关空间更新影响。原型不能证明冲突无关，已撤回生产实现，上述正例不代表误拒已解决。下一步应先构造独立标注的冲突相关性反例，并只在完整上下文和依赖可验证时放行；无法判断仍拒答。人工签名清单可作为受控回退，但不等于自动语义理解。

对文本频率增加简单正则的尝试也已撤回：项目名称前后缀、兼容字符、疑问和否定都可能使主体或陈述性质被误判。现有确定性冲突检测器无法覆盖所有自然语言表述；人工审核必须真实、完整地检查相关来源及其冲突，不能把签名或全文节点筛查当作语义正确性的自动证明。

## 后续自动归因设计约束

- 受限自动规则应基于可版本化的主体、属性、限定条件和依赖关系；问题或文档超出已支持的闭合表示、出现隐含指代或依赖不完整时，结果为未知。
- 每个已授权筛查候选必须验证身份、完整内容与位置，表格还需验证单元格覆盖；不能只检查模型最终使用的证据。
- 必须逐对解释全部冲突为什么不影响问题，并独立核验回答是否回答了问题、是否保留否定、时间和单位等限定。身份、审批冲突不自动放行。
- 最终提交和历史读取必须复核权限、文档版本、策略及依赖数据；如使用名称唯一性，须覆盖并发新增、发布、归档和改名，避免以全局目录版本泄漏其他空间的变化。
- 用隔离合成资料中的多主题、跨文档反驳、同名、隐藏条件、表格结构和权限并发反例验证；人工标注、假模型、真实模型及业务验收结果分别记录。现有数据未经过企业业务复核，不能据此声称通用误拒已消除。

评测设计可借鉴成对上下文方法：对同一问题分别构造支持、信息受损、缺失和误导性证据，分别记录回答、拒答和错误放行，避免把缺失证据与误导性证据混为一谈。相关研究指出，单靠提示词拒答或单一模型判别仍可能失效；该研究的样本和模型不代表本系统的实际效果，不能直接作为本项目的验收结论。参见 [GRAB-RAG 研究论文](https://aclanthology.org/2026.aacl-long.153.pdf)。
