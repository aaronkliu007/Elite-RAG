# 引用截断边界安全修复

> **目标：** 阻止精确子串匹配在截取引用或声明时丢掉紧邻的中文否定词、数字位数或负号。
>
> **边界：** 仅增加保守的拒绝规则；无法证明语义相关、完整支持、项目身份或所有自然语言否定形式。包含多个同样子串且其中有不安全边界时按歧义拒绝，可能增加误拒。严格拒答和权限流程保持不变。

1. 编写失败测试，覆盖截断引文、完整引文中截断声明、中文否定、负数、数字截断、多次出现的歧义和正常引用。
2. 在现有 `ExactQuoteCitationSupportVerifier` 中同时校验“声明相对引文”和“引文相对来源”的边界；不记录文本、不调用额外模型。
3. 测试问答实际拒答、正常回答、相关安全回归以及真实检索链路，记录规则局限；独立审查并提交本地 Git。

## 审查决策

曾考虑直接比较中文项目名称。独立审查指出别名、更名、跨项目借鉴以及通用词会导致误拒，且现有投影并无受控项目 ID 或别名；该启发式未启用。语义相关性仍需独立设计和评测，本修复不宣称解决该问题。

对引用边界的独立审查提出了“未经委员会批准”、数量限定、千分位、中文数字、补充平面数字及输入规模等反例，已增加针对性测试和处理。长距离否定、双重否定与其他语言仍存在漏判或保守误拒；对普通“预约检查”等非数量场景进行了误拒回归。

复审补充了“至少保留30天”被截成“保留30天”、分数截断、时间截断和指数记数截断；均已添加反例。数量前缀的处理仍是有限模式，不保证识别所有限定语或上下文。
