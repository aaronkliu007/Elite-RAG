# 声明独立标注与评测门禁

> **目标：** 不再把引用 ID 存在当成声明语义受支持；使用版本化的声明原文和支持来源标注，未复核时质量门禁失败。
>
> **边界：** 此次仅改评测，不改变日常问答、鉴权或模型调用；当前黄金集没有声明标注，故不能通过新门禁。标注应由业务人员独立编制和审核，系统无法仅凭填写的审阅标识证明审阅真实发生。已有历史结果保留原始判断，API 默认返回按当前规则重新计算的判断。

1. 先补失败测试：仅有有效引用不得算语义支持；明确标注的声明和全部引用来源匹配时才计入已复核；文本、来源或标注缺失均不得通过；历史指标缺失复核数须失败。
2. 扩展评测样例、证据 ID 到版本及内容摘要的映射、声明复核计数和门禁；新增字段兼容旧目录与历史 JSON，不自行伪造标注。API 的 `assessment` 为当前规则判断，`historicalAssessment` 保留原始判断。
3. 覆盖 PostgreSQL 保存与历史读取、受权限保护的 API、合成数据格式、无额外模型调用；运行评测单元、真实数据库集成和现有端到端相关回归。
4. 中文运行手册说明标注格式、未复核语义和历史结果边界，独立审查后提交本地 Git。

审查补充：标注绑定实际脱敏问题以及来源版本、内容、标题和定位摘要；数据集全量内容指纹需持久化并在读取时与当前目录对照。正确拒答率门槛调整为 100%，旧记录缺少指纹时不能通过当前门禁。所有内容摘要用于保守判定，并不替代业务人员的语义审核。
