# 方案定稿与 Word 导出实施计划

## 目标与既有约束

在已批准的方案工作台设计上完成风险确认、不可变定稿版本和授权 Word 下载。部署保持单公司实例；Spring Boot 内即时生成 DOCX，首版采用内置中文样式。定稿只引用已确认的需求、大纲及已采纳章节，旧版内容不可被后续修改覆盖。

## 交付顺序

1. PostgreSQL 新增风险确认及定稿版本、章节顺序、确认关联表；运行角色仅获必要权限。实现 JDBC 仓库、风险确认与成功审计的原子提交，以及事务性定稿提交。
2. 接通现有 `SolutionFinalizationService`，完成权限映射、证据源当前发布状态与 ACL 校验、风险确认及定稿 HTTP API。并发更新和失败审计保持失败关闭。
3. 实现按定稿版本生成 DOCX 的独立渲染器。只写入文本和受控样式，不解释 HTML、不载入外部资源；下载前逐项复核知识空间与来源文档权限，记录下载审计。
4. 页面展示待确认风险、定稿操作、版本摘要与下载入口；处理提交中、冲突和权限撤销状态。
5. 先编写行为测试，再实现各切片；执行 Java、前端与浏览器测试，复核迁移、权限边界及 DOCX 内容，最后提交本地 Git commit。

## 验收边界

- 缺少必需章节、阻断性核验结果、未确认高风险事实、失效证据或修订冲突时拒绝定稿。
- 定稿版本存储明确的版本引用、创建人、时间和内容 SHA-256；定稿与成功审计同一事务提交。
- 只有当前可查看方案且能读取全部引用来源的用户可以下载。源文档撤销发布或权限后，下载失败关闭。
- DOCX 保留章节顺序、正文、需求来源定位、章节证据定位和版本信息；模型文本作为纯文本写入。
