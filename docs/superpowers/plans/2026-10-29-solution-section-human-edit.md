# 方案章节人工修订与版本对比实施计划

## 目标与边界

沿用已批准的方案工作台设计，补上章节人工修订与版本对比的可用闭环。编辑仅创建不可变候选版本，不自动改写当前已采纳内容。每次编辑必须携带方案修订号及上一候选版本 ID；并发过期返回 409，保留用户本地内容。

## 实施顺序

1. 先以行为测试固定候选保存、冲突、撤权和核验失效规则。人工修订的整段正文作为带原有证据集合的新声明，核验结果为 `HUMAN_CONFIRMATION_REQUIRED`，不得继承模型的 `SUPPORTED`。
2. PostgreSQL 查询同一已采纳基线上的最新人工候选；锁定方案行串行化保存，版本链指向上一候选或基线。证据来源沿父版本链追溯原始生成快照。
3. 增加保存候选、读取版本和章节版本列表 API。逐次校验空间、需求来源和证据当前权限；采纳仍使用现有人工采纳接口与乐观锁。
4. Vue 章节面板提供正文编辑、候选保存、人工采纳与并排版本对比。冲突时同时展示本地与服务端正文，不自动覆盖。
5. 执行 Java、前端与浏览器回归，复核安全边界，提交本地 Git commit。

## 首版限制

首版使用纯文本编辑，保留现有证据 ID；新增证据、逐条声明编辑和富文本引用标记另行设计。人工修订必须由有权评审者逐项确认风险后才能定稿。定稿版本保持不可变。
