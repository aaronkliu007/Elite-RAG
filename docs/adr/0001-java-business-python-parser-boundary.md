# ADR-0001：Java 负责业务边界，Python 负责无状态文档解析

- 状态：已接受
- 日期：2026-09-24
- 决策范围：知识底座的核心业务服务与文档解析服务

## 背景

公司现有技术栈同时包含 Java/Spring Boot、Python 和 Node.js。知识底座既需要组织、权限、文档生命周期、审计和事务一致性，也需要处理 Word、Excel、PDF、PPT、Markdown 和图片，并持续接入 OCR、版面分析、表格识别等快速演进的 AI 文档工具。

若所有能力都放在 Java 中，业务治理较统一，但文档 AI 生态选择少、接入成本高；若所有能力都放在 Python 中，解析开发方便，但会扩大 Python 服务对身份、权限、事务和企业数据的控制范围。两者都不符合“数据留在内网、仅经审批调用云端模型 API”的安全约束。

## 决策

采用“Java 业务核心 + Python 无状态解析 Worker”的模块边界。

Java/Spring Boot 负责：

- 钉钉身份、组织事实和会话失效；
- 知识空间、文档版本、审核、发布和归档；
- ACL 判定、越权隐藏、审计与事务；
- 上传安全门禁、Blob 引用、任务租约和失败重试；
- PostgreSQL、MinIO 以及获批云模型网关的凭据管理；
- 对前端公开稳定的业务 API。

Python/FastAPI Worker 负责：

- 对受控字节流执行格式解析、OCR、版面和表格结构提取；
- 将结果规范化为 `CanonicalDocumentV1`；
- 返回结构化、可重试性明确的错误；
- 在超时或进程异常时安全失败，不修改业务状态。

Worker 必须保持无状态，不直接读取 PostgreSQL/MinIO，不持有钉钉或云模型密钥，也不决定文档是否可发布。

## 通信契约

- Java 通过内网 HTTP multipart 请求传递 `ParserJobV1` 元数据与单次受控文件流；
- 请求和响应分别由 `parser-job-v1.schema.json` 与 `canonical-document-v1.schema.json` 固定版本；
- Java 和 Python 两端都校验契约；来源文件名、MIME、任务 ID 和 Schema 版本必须一致；
- Java 设置请求超时和响应体上限，Worker 在独立子进程中执行 Docling，超时后可终止；
- Python 返回成功结果不等于发布。Java 先持久化派生内容，再把版本推进到“待审核”，最后只能由有权限的人员显式发布；
- 重试由 Java 租约任务编排控制，同一解析结果按文档版本幂等替换，不由 Worker 自行重试或写库。

## 安全与数据边界

- 原始资料默认不离开内网；
- 当前解析链路不调用云端模型；未来确需调用时，必须经过单独审批、字段级脱敏、允许列表、出网代理和审计，不能把批准推断为默认授权；
- Worker 只接触当前任务的临时文件，任务结束后清理；
- 日志只记录任务 ID、错误码、耗时等白名单元数据，不记录正文、文件字节、Token 或密钥；
- Java 在传输前完成文件大小、真实类型、加密、压缩炸弹与恶意内容检查；Python 仍需保留自己的资源上限，不能信任上游输入。

## 被否决的方案

### 全部使用 Java

优点是运行时与团队主业务栈统一。缺点是 Docling、OCR 和版面分析能力主要在 Python 生态，Java 侧重新封装或调用本地进程会增加兼容与升级成本。该方案不采用。

### 全部使用 Python

优点是 AI 与解析迭代快。缺点是需要在 Python 中重新建设组织权限、事务、审计和企业级工程约束，也会让解析服务获得过多数据权限。该方案不采用。

### Java 与 Python 共享数据库或对象存储凭据

优点是少一次服务调用。缺点是破坏服务边界，使 Worker 能绕过生命周期与 ACL，并把凭据泄漏和错误写入的影响扩大到整个知识库。该方案明确禁止。

## 结果与代价

正面结果：业务治理保持在团队熟悉的 Java 栈，Python 可以独立升级解析工具，失败隔离清晰，最小权限更容易审计。

代价：需要维护跨语言 Schema、HTTP 传输、超时、版本兼容和双端契约测试；大文件传输会增加一次内网 I/O；运行时多一个服务。以上代价通过版本化契约、内容寻址、请求上限、无状态横向扩展和统一验证命令控制。

## 复审条件

出现以下任一情况时复审本 ADR：

- Java 生态出现能满足真实样本质量与安全基线的同等解析能力；
- 解析吞吐或文件大小使 HTTP 流式传输成为明确瓶颈；
- 获批云模型改变数据出境和密钥托管边界；
- Worker 需要长期状态或业务事务；
- 契约需要不兼容升级到 V2。
