# 需求整理与大纲候选运行说明

在方案详情页保存人工修改后，可生成需求整理候选。该能力只整理已有需求及来源，不从新上传文件自动提取需求。需求经异人确认后，可生成大纲候选。页面对比当前内容与候选，并展示分类、章节设置和来源。勾选审阅后可采纳为待确认修订，仍需异人确认；版本冲突时保留候选和当前编辑内容。

## 接口

- `POST /api/v1/solutions/{solutionId}/proposals/requirements`：需求整理候选。
- `POST /api/v1/solutions/{solutionId}/proposals/outline`：大纲候选。
- `GET` 同一路径：查询原请求，提供 `expectedRevision` 查询参数。
- 两种请求都使用 `Idempotency-Key` 请求头。POST 请求体为 `{"expectedRevision": 0}`。操作者由登录态确定。

生成和查询均复核动作权限、当前需求版本、修订号、来源发布状态及 ACL。关闭 `rag.ai.enabled` 时生成返回 `503 MODEL_PROPOSAL_UNAVAILABLE`，不登记候选或外发请求。启用后沿用已审批网关、脱敏和额度配置，禁止记录密钥、完整提示词和供应商原始错误。

## 恢复规则与边界

候选调用不做 HTTP 自动重试，同键重放不重复调用模型。页面在当前浏览器会话中按登录用户、方案、动作和修订号保留请求键。请求未到达服务器时，可以用原键重发，不能换新键盲目重试。`RUNNING` 可查询；`FAILED` 表示明确失败；结果不明时保留至租约到期，查询得到 `INDETERMINATE` 后由管理员核查供应商记录和费用。

会话结束或换浏览器不能自动恢复请求键；首版没有跨设备候选历史列表。真实审批模型、真实脱敏资料、费用和并发容量仍需独立联调。本地假网关及浏览器接口桩验证不代表生产准入。
