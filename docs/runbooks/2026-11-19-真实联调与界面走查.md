# 真实联调与界面走查记录

日期：2026-11-19。测试使用隔离环境和虚构资料，不代表企业真实数据验收或生产环境验收。

## 真实后端和模型

- 在隔离 PostgreSQL、OpenSearch 和对象存储上启动 Spring Boot 问答服务，并通过官方 DeepSeek API 使用 `deepseek-flash`。独立适配器的问答引用、需求提取和章节生成三项测试通过。
- 通过真实检索和模型执行六个虚构问题，六次均返回答案且包含预期来源；这六次并未逐条核对答案内容，不能据此计算准确率。
- 浏览器端核对了一个问题的答案与来源原文，结果一致；另一个问题被冲突门禁拒答，证实误拒仍可复现。来源预览成功打开。
- 在虚构方案中，从真实文档提取了三条需求候选，其中一条是无业务价值的测试资料说明，需要人工筛选。未执行正式业务验收。
- 此次使用本地词法检索回退，向量检索未启用；隔离对象存储使用了测试环境的根账号。结果不能证明混合检索完整链路或最小权限账号已经通过验证。
- 后续单独运行了生产适配器的隔离装配测试：真实 PostgreSQL、AIStor 和 OpenSearch 配合本地模拟 Embedding 网关，验证了向量投影、查询时词法与向量双路融合，以及无权限主体在索引侧得不到候选；模拟网关返回 503 时仅保留词法结果并标记向量降级，恢复后重新融合。AIStor 使用测试应用账号。该测试没有运行真实 Embedding 模型，也没有通过完整问答链路验证数据库最终鉴权，不能证明生产混合检索质量或完整权限闭环。
- 另行运行词法检索的撤权回归：在真实 PostgreSQL 和 OpenSearch 中，撤权后即使索引候选尚未更新，最终数据库鉴权仍过滤该候选。该验证与上面的双路融合测试是两个独立场景，不能合并宣称混合检索撤权端到端已通过。

## 冲突门禁与误拒

42 题无模型诊断包含 38 个预期应回答的问题，其中 13 个在当前严格策略下因冲突被拒绝。其余题目处于模型不可用诊断模式，不能视为回答成功。此前模型影子判别曾出现把未知冲突错误放行的情况，故不能通过忽略未知冲突来改善数字。

对其中 Q05、Q06 使用模拟签署的逐题审核清单后，真实模型返回了包含预期来源的答案。这仅是两条合成问题的受控验证，不是组织人员的真实审批，也不能证明生产环境通用误拒已经解决。默认严格拒答和既有授权检查保持不变。

## 页面走查

在真实服务和桌面浏览器中，走查了登录、工作台、用户管理、知识空间、文档、上传、检索、问答、来源预览、方案和评测入口。用户管理控制器在本地运行配置中未装配的问题已修复，真实数据库专项测试通过。该修复针对 `local` 配置，不代表其他生产配置已完成验证。

修正了导航双重高亮、部分状态英文及窄桌面下文档操作不可见的问题；来源预览增加了可直接点击的入口。检索来源进入文档后目前不会自动定位片段，界面已明确提示。1366、1280 和 390 像素的响应式检查另有浏览器自动化覆盖，但自动化使用模拟接口，不等同于真实手机的人工视觉验收。页面走查不代表覆盖了所有权限、状态组合和浏览器。

空间管理员可从空间页顶部直达成员与角色管理；长文档列表场景的浏览器自动化验证了跳转。普通成员不显示该入口。
