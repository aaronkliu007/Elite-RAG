# 问题与证据相关性合成评测

## 用途与边界

这套离线样例用于比较检索方案：是否找回与问题有关的证据及相关冲突两边，同时观察明确无关的证据和无关冲突是否混入。样例与标注均为虚构资料，尚未经业务专家审阅，也不能代表真实企业知识分布。它不是生产准入门禁，不修改线上检索或拒答策略。

样例位于 `apps/core-api/src/test/resources/relevance-benchmark-v1.json`，包括 4 个问题、每个问题 13 份文档：不同项目的无关审批冲突、同一项目的预算冲突、缺少对象的审批冲突、同一系统的备份期限冲突。每个问题使用独立空间和用户；文本只有测试数据。

标注有三个状态：`RELEVANT` 表示本样例中能够直接支持或反驳问题的证据；`IRRELEVANT` 表示本样例中明确属于其他对象或不涉及问题；`UNCERTAIN` 表示对象不明确或同主题但是否有助于回答尚需判断。不确定与未标注不能计入无关。冲突对同样标注与问题的关系，标注用于评测，不用于过滤生产证据。

## 基线结果（2026-10-30）

在当前 BM25、无 Embedding、无 Reranker 的降级条件下，隔离环境依次执行 PostgreSQL 持久化、OpenSearch 投影、索引 ACL 过滤及数据库最终授权，再取最终证据包；结果如下：

| 观察项 | 本次结果 |
| --- | --- |
| 标注为相关的证据被召回 | 11/11 |
| 明确标注为无关的证据被召回 | 9 条 |
| 标注为不确定的证据被召回 | 20 条 |
| 相关冲突对的两边都被召回 | 2/2 对 |
| 无关冲突对的两边都被召回 | 0/1 对 |
| 不确定冲突对的两边都被召回 | 0/1 对，实际只召回一边 |
| 实际问答按冲突拒答 | 2/4 个问题 |
| 实际问答调用本地假模型并回答 | 2/4 个问题 |

其中一条已回答问题的本地假模型原样引用了标注为无关的材料，系统仍返回了答案；另一条已回答问题存在对象不明确的冲突，证据包只包含冲突的一边。前者说明精确引用校验不能单独证明回答与问题相关；后者说明最终证据上限可能遮蔽有待核实的冲突。假模型故意复制首条证据，是用于暴露门禁边界的测试替身，不能推断 DeepSeek 会作出同样回答。相关、无关、不确定的数量是测试集作者给出的判断，不是已确认的业务事实，不确定冲突不能被当作无关而忽略。

这次测试还确认：未经授权的其他空间没有返回证据；数据库撤权后即使索引仍返回旧候选，最终授权也剔除了全部证据。两次冲突拒答均在假模型调用前发生，并核对了调用审计。测试不验证真实模型回答质量、业务专家对标注的一致性、复杂权限场景的完整性，也不保证发现索引之外、排序之外或证据上限之外的冲突。样本量仅为 4，不能推断真实业务比例；每次结果可能受检索排序、索引和环境变化影响。**当前证据不足以支持生产准入。**

## 复现

在项目根目录运行，需已准备项目现有的 Docker 测试环境和 AIStor 许可。命令仅创建临时测试基础设施，不需要模型密钥，不调用外部模型：

```powershell
$env:RAG_RELEVANCE_DIAGNOSTIC = 'true'
try {
    .\mvnw.cmd -B -pl apps/core-api -am '-Dtest=PostgresOpenSearchRetrievalAcceptanceTest#measuresAnnotatedRelevanceThroughTrustedRetrieval,RelevanceBenchmarkTest' '-Dsurefire.failIfNoSpecifiedTests=false' test
} finally {
    Remove-Item Env:RAG_RELEVANCE_DIAGNOSTIC -ErrorAction SilentlyContinue
}
```

`RELEVANCE_CASE` 输出样例 ID、返回的虚构文档 ID、冲突检测结果、问答状态、假模型调用数、假模型答案的标注类别和各类别统计；`RELEVANCE_BASELINE` 输出汇总。测试成功代表样例、计算和流程运行成功，不代表质量达标。后续比较时须同时检查相关冲突完整召回、相关证据漏检、无关冲突混入、不确定证据及证据不足，不能只以降低拒答数量为目标。
