# 问题与冲突证据相关性：扩展合成样例

## 范围

`apps/core-api/src/test/resources/relevance-benchmark-v2.json` 是研发人员编写的虚构样例，不含公司真实资料，尚未经业务专家审阅。8 组问题、80 条证据分别标注 `RELEVANT`、`IRRELEVANT`、`UNCERTAIN`，覆盖同项目不同主题、预算冲突、指代、声明别名、名称子串、多对象、版本和环境范围。冲突对的标注仅供测试统计，不能直接用于运行时过滤或授权。原 V1 样例保留。

## 本次隔离测试（2026-11-01）

测试使用临时 PostgreSQL、OpenSearch、AIStor 和本地假模型，经过投影、索引 ACL 和数据库最终鉴权，再统计最终证据和全部已鉴权冲突筛查候选。测试环境不调用云模型。原样例的安全断言对 V2 同样生效：已标注相关或不确定冲突的两边必须出现在筛查候选中，问答必须拒答，假模型调用数必须为零。

| 项目 | V1，4 组 | V2，8 组 |
|---|---:|---:|
| 标注相关证据进入最终证据 | 11/11 | 16/16 |
| 相关冲突双边进入最终证据 | 2/2 | 3/3 |
| 不确定冲突双边进入筛查候选 | 1/1 | 1/1 |
| 因冲突拒答 | 4 | 6 |
| 假模型调用后回答 | 0 | 2 |

V2 的同项目跨主题问题因无关预算冲突被拒答；别名问题的一次假模型回答选中了“不确定”材料。这是假模型刻意引用首条证据的诊断，并不代表真实模型会采用同样回答。生产环境不能仅靠引用编号有效判断与问题相关。

新样例还发现两条明确的“生产环境备份保留 30 天／90 天”原先均被召回却未识别为冲突。已补充针对该明确句式的规则与等值单位、不同环境反例，复测时该案例在假模型调用前拒答。该规则不代表能够识别所有备份期限或全部语义冲突。

本机 42 题的模型禁用重测中，38 条标为应回答的案例有 13 条因冲突被拒绝，25 条因模型不可用失败；预算冲突题被拒绝。模型失败不能算正确拒答，以上结果也不能推断真实模型回答准确率。

## 复现

需要现有 Docker 测试环境和项目测试依赖。命令只创建临时测试基础设施，使用本地假模型，不使用模型密钥：

```powershell
$env:RAG_RELEVANCE_DIAGNOSTIC = 'true'
$env:RAG_RELEVANCE_V2_DIAGNOSTIC = 'true'
try {
    .\mvnw.cmd -B -pl apps/core-api -am '-Dtest=PostgresOpenSearchRetrievalAcceptanceTest#measuresAnnotatedRelevanceThroughTrustedRetrieval+measuresExpandedRelevanceThroughTrustedRetrieval,RelevanceBenchmarkTest' '-Dsurefire.failIfNoSpecifiedTests=false' test
} finally {
    Remove-Item Env:RAG_RELEVANCE_DIAGNOSTIC, Env:RAG_RELEVANCE_V2_DIAGNOSTIC -ErrorAction SilentlyContinue
}
```

查看 `RELEVANCE_SCREENING` 中全部鉴权候选和 `RELEVANCE_CASE` 中最终证据、问答状态及假模型调用数。测试通过只说明覆盖的断言成立，不能单独证明相关性、误拒答率、真实模型质量或生产准入。样例、标注和规则均需结合获准的真实脱敏材料复核。

## 真实模型的离线影子对照（2026-11-01）

本次把 V2 的 8 个虚构问题及每题 10 条虚构文本直接发送至已批准的 DeepSeek 官方接口 `deepseek-flash`，要求逐条标注相关、无关或不确定；模型未收到参考标签。实验共 8 次请求，记录的总 token 数为 4279，可能产生费用。实验不经过系统问答链路，不能用于证明运行时授权、脱敏、模型输出约束或线上效果；不要把此脚本用于真实企业资料。

一次实验中，若假设把模型判为“无关”的证据直接排除：16 条参考标注相关证据没有被排除，32 条参考标注无关证据被排除，但 **32 条参考标注不确定证据中有 3 条被排除**。3 组相关冲突及 1 组不确定冲突的双边在此次结果中保留。这是研发人员的合成标注，并非业务专家金标准；一次模型输出不能推断其他数据、同一数据重复调用或模型版本变化的表现。因误排不确定证据，不能将该模型判断用于线上自动过滤。

模型只读的标签快照存放于 `apps/core-api/src/test/resources/relevance-v2-shadow-snapshot.json`，不包含密钥或真实业务数据。`RelevanceBenchmarkTest` 离线重放该快照，验证筛选前后相关、不确定及未标注材料的损失；这只证明本次已记录的输出能被评测工具识别，不调用模型，不代表模型评测通过。对于筛选前已经缺失的冲突证据，工具单独计数，不能将筛选器的局部保留结果误当成整体召回安全。

对同一批材料、相同提示词又独立调用了 8 次，第二次记录 4284 token；两次总计 16 次请求、8563 token。80 条证据的两次标签有 4 处不同；如果仅排除两次都标为“无关”的证据，仍会排除 3 条参考标注为不确定的材料。因此重复判断或简单投票不能作为安全保证。第二次只含编号和标签的快照为 `apps/core-api/src/test/resources/relevance-v2-shadow-second-snapshot.json`；离线回归测试会复核两次结果及误删统计，不会再次调用模型。

## 冲突拒答来源诊断（2026-11-01）

为保留已批准的严格拒答与现有 Web 响应契约，冲突检查异常继续返回 `CONFLICTING_EVIDENCE`、不调用模型。服务端只记录请求 ID 和固定诊断码 `CONFLICT_SCREENING_UNAVAILABLE`，不记录问题、文档正文、抽取值或异常堆栈。检测到冲突时只记录请求 ID 和固定类别（`IDENTITY`、`APPROVAL`、`STRUCTURED_TABLE`、`TYPED_FACT` 或自定义检测器的 `OTHER`）；类别是工程诊断，不能证明冲突与问题相关。历史请求不会自动补充这些日志。

本机模型禁用重跑 42 题：15 条返回冲突拒答（包括 13 条标注应回答的案例、预算冲突题及 1 条标注应拒答案例），均记录为 `STRUCTURED_TABLE`，没有记录检查异常。因此此次误拒答并非由异常伪装成冲突造成。该诊断只反映此次合成数据、召回和当前进程，不能证明其他请求没有异常，也不能将标注应拒答的案例仅凭冲突状态判为正确。

### 检查异常与评测统计

问答响应继续遵循已批准的原有契约：冲突检查抛出异常时，返回严格拒答且不调用模型。对显式启动的评测请求，进程内评测轨迹会另外记录一个不含问题和资料内容的故障标记；数据库评测适配器消费该标记后，评测结果的内部原因显示 `CONFLICT_SCREENING_UNAVAILABLE`，并且该次拒答不计为正确拒答。普通问答不会创建评测轨迹。

该改动只影响启用新代码后执行的新评测；历史评测记录不会自动重算。标记不会改变用户端返回的拒答原因，也不能用于推断该问题存在或不存在真实冲突。发生异常时应依据固定日志码排查，不能将拒答直接当作质量通过。

评测管理页将该内部原因显示为“冲突检查暂不可用”，并将其包含在“系统处理失败”筛选中；它仍保留实际问答返回的“已拒答”状态。页面只展示案例和请求编号等诊断信息，不展示问题及文档正文。

## 本地词项重排兜底实验（2026-11-01）

新增可选本地重排：仅在外部重排不可用时，对已授权候选按问题与标题／正文的本地词项重合程度调整顺序；不删除候选、不改写原始分数，冲突筛查仍接收全部最终鉴权候选，并继续报告 `RERANKER_UNAVAILABLE`。该能力由 `RAG_LOCAL_LEXICAL_RERANK_ENABLED` 控制，**默认关闭**。它只是词面启发式，不具备语义理解能力，不能保证事实相关、引用正确或完整冲突召回；单次合成测试不能作为生产启用依据。

本机 42 个虚构问题在同一隔离环境对照（每题最终最多 10 条；3 条无指定参考文档不计入下列数字）：

| 检查项 | 原排序 | 启用本地重排 |
| --- | --- | --- |
| 全部指定文档被命中的问题 | 38/39 | 39/39 |
| Q27 角色问题指定文档 | 未进入前 10 条 | 相关段落第 1 条 |
| Q37 预算冲突两份指定表格 | 均命中 | 均命中 |
| 38 条预期可回答问题因冲突拒答 | 13 | 13 |

这些数字只表示指定文档是否出现，不能等同于真实文档召回率、问答正确率或权限安全。以 `deepseek-flash` 对 Q27 进行 1 次虚构资料问答复核，回答列出管理员、编辑者和浏览者，引用通过授权来源接口核对到预期 Markdown 文档；这一次模型调用可能产生费用，不能外推其他问题。验证结束后隔离环境已恢复云模型和本地重排默认关闭。

启用本地重排的隔离 V1/V2 诊断仍通过已标注相关和不确定冲突的保留及拒答断言；V2 仍有 6/8 题因冲突拒答，其中包含同项目不同主题误拒答。该实验未解决候选证据与问题的相关性问题；仍需更大规模、经业务复核的数据及权限、性能测试后，才可评估是否启用。

### 模型输出无效的评测口径

问答遇到 INVALID_MODEL_OUTPUT 仍严格拒答；新运行的评测不再将该故障计入正确拒答，评测案例保留原始原因，正确拒答门禁因此不会因输出格式故障而虚假通过。已保存的历史评测指标不会自动重算，应在修正版本上重新运行评测后比较。数据集目前只标记是否应拒答，没有标注预期拒答原因；其他非故障拒答被计入并不证明拒答原因与案例的预期语义相符，需要进一步人工核对。
### 结构化表格重复事实的跨证据检查

此前表格检查对相同事实键只保留首条，可能漏掉同一表格中后续值与另一份证据的冲突。现已让每个提取事实参与跨证据比较，并将重复事实也计入检查数量上限；单份证据内部的多值仍不自行判定为跨证据冲突。相同维度、单位可换算、不同维度和异常关闭等既有规则不变。该修复只覆盖可由当前规则抽取的结构化表格事实，不代表复杂表格和所有语义冲突均可识别，也不解决跨主题证据导致的误拒。
### 数值精度与回归范围

数值事实统一换算后保留原始十进制精度，不再固定四舍五入到 12 位小数，避免不同事实被误判为相同；等值单位仍按精确换算比较。新增文本和表格高精度用例。2026-11-04 的非容器后端回归运行 612 项、失败 0 项、跳过 1 项：跳过的真实解析服务测试未配置 RAG_TEST_REAL_PARSER_ENDPOINT。该轮排除了集成及验收测试；PostgreSQL 测试镜像拉取未完成，不能据此宣称数据库和搜索端到端回归通过。
### 混合相关性冲突对的离线门禁

资料整体相关性与资料中某一对事实冲突的相关性分别标注。对于已召回的相关或不确定冲突对，即使其中一侧资料整体标为无关，只要筛选移除了该侧，也必须将冲突对计为受损，安全保留判断不得通过。筛选前就不完整的冲突对继续单独统计，不能据此推断整体召回安全。本条仅修复测试辅助代码和增加合成用例，不改变线上证据集合、拒答逻辑或现有模型影子快照；标注仍需业务复核。
### 表格维度列顺序

结构化表格事实的维度按字段名和值规范排序后再比较。同一项目、预算类别和金额列换位时仍能识别不同金额；换列后的等值单位和不同项目反例不应产生冲突。本规则依然只针对现有可抽取的简单表格，无法据此推断复杂表格或全部语义冲突均能识别，也不消除跨主题误拒。
### 多行合并单元格的保守处理

合并单元格中存在数字时，当前规则无法可靠解释表格结构，按检查异常进行严格拒答。数字检测覆盖多行和 Unicode 数字，避免换行使数字漏检。问答编排测试确认此场景不会调用模型，并在评测轨迹中标记冲突检查不可用；此处理仍不表示可以解析所有复杂表格。

### 历史评测的当前门禁复核

历史聚合指标可能按旧口径把模型输出无效计入正确拒答。读取评测时，若已保存的应拒答案例明确记录 INVALID_MODEL_OUTPUT 或 CONFLICT_SCREENING_UNAVAILABLE，当前门禁增加正确拒答项失败，原历史判断和原始指标不改写。旧记录如果缺少应拒答案例的逐条诊断或拒答原因，当前门禁显示“拒答诊断不完整”并保守失败；历史判断和原始指标不改写。对于旧冲突拒答，若没有检查成功完成的明确标记，当前门禁同样保守判为“拒答诊断不完整”，应在新版本重新运行评测。新评测只有在冲突检测器实际成功返回后才记录完成标记；异常、缺少轨迹或标记缺失均不作为已验证冲突。

### 带符号金额的证据和冲突检查（2026-11-05）

证据去重保留紧邻中文的数字负号；简单文本和结构化表格支持 ASCII 加减号与 Unicode 减号的数字事实比较，并保留单位换算。例如负一万元与负一万元的等值元金额相同，负五万元和正五万元构成冲突。使用虚构资料经过 PostgreSQL 投影、OpenSearch 召回和数据库授权复核后，两侧进入冲突筛查并在模型调用前拒答；该验证不代表可识别“亏损五万”等全部自然语言负数表述，也不解决跨主题误拒。

### 按冲突对判断跨主题证据的离线实验（2026-11-05）

冲突检测器新增有数量上限的冲突对诊断，输出仅包含证据标识及冲突类别；上限、表格读取或单位判断异常不得视为无冲突。匿名项目的备份期限与明确项目的不同期限按潜在冲突处理。诊断不改变正式问答的证据范围或严格拒答策略。

为探索更可核验的判定，新增仅供影子试验的整句字面依据检查：引用必须来自唯一文档的完整节点，并同时明确写出冲突事项、问题事项和限定句式的独立声明。对上述两条案例，固定的 18 份合成文档均未找到这种声明；加入一条专门构造的声明后可以找到。反例同时证明：即使找到声明，另一份资料仍可能包含相反关系，因此该检查只标记“发现某条声明”，绝不作为冲突已解决或生产放行的证明。

试验入口为 `scripts/conflict_scope_probe.py` 和 `scripts/conflict_scope_corpus_probe.py`，均默认禁止运行，分别需要显式设置 `RAG_SYNTHETIC_SCOPE_PROBE=true` 或 `RAG_SYNTHETIC_CORPUS_PROBE=true`，并在受控环境注入已审批的 `RAG_AI_API_KEY`。完整资料试验只读取固定名称的隔离 PostgreSQL 容器，并独立核验实际外发节点载荷的固定摘要；登记的原文件摘要仅来自数据库，未重新读取对象存储并校验原件字节。任何校验失败均不调用模型。异常、截断、拒绝、工具调用或格式错误不判无关；输出仅有案例编号、分类和计数，退出状态不代表生产安全。

### 已审核文档漏召回的本地补筛（2026-11-19）

对已获人工审核的问题，即使初筛显示无冲突，也会检查每份已召回的相关文本型文档是否完整；节点缺失时，只从内网补齐同一授权文档的当前版本，再对全部候选执行冲突检测和审核校验。补充节点不进入模型提示或对外证据；最终返回前再次校验授权、文档指纹、节点和策略版本。无法补齐、含表格等暂不支持的相关文档仍严格拒答。

隔离环境以 PostgreSQL、OpenSearch 和虚构资料，故意从检索候选中移除已审核备份文档节点，在启用本地重排及假模型条件下成功回答并读取历史记录。单元反例验证了初筛无冲突、补齐后发现隐藏冲突时拒答；跨文档扩展、丢失原候选、重复标识和扩展失败也拒答。独立代码审查指出初版在初筛无冲突时跳过补齐的问题，修正后复查未发现确定的新绕过。此结果仅证明所测的审核文档场景，并不解决未审核问题的通用归因，也不代表真实业务验收。

测试中关闭本地重排时，候选正文未进入模型所用的最终证据，假模型因找不到引用正文而拒答；启用重排后该样例通过。该单例提示检索选择仍需独立评估，不能据此推断所有未重排查询都会失败。
